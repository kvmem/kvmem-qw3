## 测试约定

**正确性。** 用完全相同的目标模型、前缀状态和采样配置比较无投机、原生 MTP
与 DFlash。涵盖中文、英文、数学、代码、短块、全部拒绝边界、EOS、stop、
penalties、取消/恢复和跨请求隔离。Greedy 必需回归要求输出一致；内部浮点
误差另行报告，不能把现有输出失败改标为通过。随机模式验证接受/残差分布，
使用可重复种子和分布/任务质量评估，不要求不同算法消耗随机数后逐 token 相同。

**KVMem。** 在相同检索和保留策略下检查 all-fit、稀疏检索、冷回放、热续写、
前缀分叉、归档重载、thinking compaction、长历史重定位和 GC/资源耗尽。
恢复后检查目标 KV、recurrent state、草稿历史及位置一致。记录草稿窗口、
快照和缓存的内存上限，覆盖持续多轮与并发取消的压力测试。

**矩阵。** 在调优前冻结具体 case ID、数据和组合：原生历史长度取 4K/32K/128K，
工作集覆盖 256/4K/8K，并发取 1/4/16；覆盖全量可容纳和有界稀疏路径，
明确历史构建是否计入计时。无需把所有维度强行做笛卡尔积，但必须提前列出
必需单元并覆盖每个维度；不能看结果后删掉失败单元。超出硬件容量的组合保留
OOM/拒绝/排队证据，不能改小并发而沿用原标签。

公开工作负载沿用已冻结的 GSM8K、MATH-500、HumanEval、MBPP、MT-Bench，
每任务 128 个正式请求，预生成的 xhigh prompt/token ID，最多 4096 输出 token，
T=1、top-p=.95、top-k=20、top-k-first，并发 1/8/32。
预热样本、有效服务并发和准入队列必须记录。公开全上下文服务不自动成为
KVMem 检索语义的正确性基准；两类工作负载分别报告。

## 性能验收

1. 本机固定 RTX PRO 6000 Blackwell，对同一 Q8＋FP8 KVMem 策略运行
   none/MTP/DFlash；若某路线缺少对应模型或不支持，记录原因并解决或明确
   对照局限，不伪造对应速度。公开引擎加入前须验证精度、质量和工作负载可比性。
2. 固定矩阵相对**最强合格对照**的配对吞吐比，几何平均目标 **≥1.05×**；
   各必需单元须在测量不确定性内达到对照水平，且无隐藏质量或明显延迟退化。
   每单元对照选择规则和统计方法在正式测试前固定。
3. 每种配置至少三次独立运行，交替执行顺序；记录全部样本与离散程度。
   接近门槛时增加重复，不能只选择最好一次。没有有效基线或质量证据的单元
   不计入“已达标”。
4. 同时报告实际完成 token 的端到端吞吐、decode 吞吐、TTFT、逐 token 延迟、
   请求延迟、接受长度/比例、草稿/验证/采样/回放阶段时间、峰值显存。
   并发端到端吞吐使用共同测量窗口，不累加各请求 tok/s。
5. 复现并争取达到/超过公开测试水平。同 GPU 的可比测试优先；BF16 参考与
   H200 公开绝对吞吐另列配置和差异，逐项标明达到/未达到，不能作为本机
   Q8＋FP8 的等价速度比。公开比较仍未具备可比条件时，该验收项保持未完成。
