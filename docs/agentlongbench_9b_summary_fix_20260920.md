# AgentLongBench 512K 9B 摘要采样和 32K 输出修正

2026-09-20 用户要求：后续不要再使用 temperature=0 贪心摘要，输出预算提高到32K。
这是对原27B协议的明确授权调整；其余提示、检索、回答和评分流程继续复用。

## 参数及容量

- 新生成的 thinking 摘要使用 temperature=1.0、top_p=0.95、top_k=20、
  min_p=0、presence_penalty=1.5、repetition_penalty=1.0。
- llama.cpp 的重复惩罚字段为 repeat_penalty；vLLM 为 repetition_penalty。
  两个后端原有惩罚窗口语义不强行改写，不声称跨后端完全等价。
- 摘要 max_tokens 从25000提高到32768，包含 reasoning 和正文的总输出。
  既有摘要 thinking budget=10000 保留；不是额外增加32768正文tokens。
- 原摘要输入232000加新输出32768超过262144上下文，故输入上限改为228336：
  `228336 + 16聊天包装预留 + 32768输出 + 1024安全余量 = 262144`。
  原分段算法和Codex提示不变，但切段边界会相应变化，不再宣称新提示逐字等同旧请求。
- 512K的前置两轮Q8摘要及后续FP8补充摘要都采用新策略。
- 最终回答仍为temperature=.6、top_p=.95、seed=20260722、thinking=8192、
  max_tokens=32768；完整回答输入仍限定65536，Jina32/8检索和原评分器不变。
- 1M按锁定协议复用固定第三方摘要，没有新的摘要请求；若后续增加摘要生成，
  也须使用非贪心新策略，不能恢复温度0。已完成≤256K和KVMem不重跑。

## 版本隔离

实验根目录为`benchmark/agentlongbench_9b_matched27b_20260916/`。

25000输出上限终止。第13题中途停止，不算模型失败；未产生最终回答或评分。

`512k/compact_rag_samplingfix_20260920/`，100题全部从新摘要重建。
只复制模型无关检索和样本，不混入旧成功摘要、失败或答案。

冻结的历史源码未修改；`summary_policy.py`给每个摘要客户端单独适配真实请求，
更新摘要预算和配置指纹。提示/SSE解析与评分继续调用原函数。最终回答客户端

修复初始摘要失败分支不刷新progress的显示滞后；后端切换增加端口释放检查。
