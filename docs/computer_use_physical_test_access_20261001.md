# 物理机测试接入

Windows VM 的本轮构建、任务执行和 KVMem 对比已完成，详见
[验收记录](computer_use_acceptance_20261001.md)。目前未提供可连接的物理
Windows 或 Mac 目标机；这些平台的实际验收仍然开放。

## 所需目标信息

提供已配置的 SSH 别名，或测试账户的 `用户名@内网地址`，并注明系统版本、
CPU/芯片、显存或统一内存容量。不要发送密码或私钥。桌面测试还需要该测试
账户已登录的图形会话；连接信息用于先核对环境和传送构建，不代表桌面操作
权限已经就绪。Mac 的权限和只读预检步骤见[Mac 接入说明](computer_use_mac_test_access_20261001.md)。

## Windows 的现有构建与部署边界

原生 Windows 客户端 bundle 06 包含 Python、Codex 和应用代码，已在 VM 内
完成任务验收。它不包含模型权重或桌面执行器凭据。可使用相同客户端开始
物理机验证，但物理机上的执行器部署、权限和坐标映射尚未验证。

不要把 VM 自动安装流程当作物理机安装器：

- `vm/provision.py` 通过任务所有的 Docker/QEMU 控制台输入命令。
- `vm/bootstrap.ps1` 使用 VM 的共享目录和 `C:\Qw3Computer`，并设置测试账户
  的 Edge 下载策略。
- 当前 `vm/executor.ps1` 使用该固定目录，并以通配 HTTP 前缀监听端口。
  物理机的启动位置、监听范围和测试账户权限需要按实际目标配置并验证。

这些限制来自当前仓库实现。尚未在物理机执行这些安装脚本，也未把 VM 的
管理员账户结果当作普通用户或 UAC 验收。

## 接入后的验收顺序

1. 核对机器和图形会话，准备目标专用的运行目录、执行器启动方式和连接。
2. 验证真实截图与输入坐标、缩放、焦点、中英文输入、权限拒绝和暂停接管。
3. 重跑文档保存、浏览器表单、跨应用复制及恢复任务，独立检查输出文件。
4. 记录模型实际运行位置、资源用量、目标版本和每次失败。

初期可继续使用当前 Linux 主机的本地 GPU；这能验证目标机上的客户端和
桌面执行器，不代表已完成 Windows 原生 GPU 或 Mac 自身推理部署。
上述顺序是待执行的验收步骤，不是通过记录。
