# Q8_0 / FP8 KVMem：控制器计时与锁页传输缓冲池

本阶段保持目标模型 Q8_0、目标 KV E4M3 FP8，以及官方 DFlash 草稿不变。
优化只改变传输缓冲区的分配和复用；默认关闭，完整目标仍为 active。

## 瓶颈与实现

新增 `dflash_scheduler_accounting` 将控制器总墙钟时间分解为初始化、
恢复请求、草稿、验证准备、验证计算、发布结果、结束请求及其他开销。
各阶段互斥，没有为计时新增 GPU 同步。记录最后一个请求返回后的清理时间，
按 request ID 关联请求组，避免 stdout/stderr 输出顺序造成误归类。

初次 C16 诊断的正常请求组总耗时 38.13–40.64 秒，其中初始化
8.92–9.76 秒、结束请求 4.32–5.29 秒；联合草稿约 0.35 秒。
C4 Nsight Systems 跟踪进一步记录到 `cudaHostAlloc` 11.270 秒、
`cudaFreeHost` 4.219 秒。这是带跟踪、包含进程加载的 CUDA API 累计时间，
不能直接用作未跟踪请求的加速比。

原配置每个请求预分配 4 个 writeback、2 个 stage-out、2 个 read slab，
每个 128 MiB，总计 1 GiB。旧 CPU tier 池不覆盖这些传输缓冲区。

`QW3_KVMEM_POOLED_IO=1` 启用按需分配和共享复用池；
`QW3_KVMEM_IO_POOL_MIB` 设置空闲锁页缓存上限，默认 1024 MiB。
这是空闲池上限，**不是所有活跃请求的总主机内存上限**。活跃传输仍受
原来的每请求队列容量约束。没有改变 slab 大小、传输分组、检索策略或数值计算。

每个 lease 独占底层缓冲区，最后一个持有者释放时才可能归还。
复用前显式等待 KV 传输流完成，保留原来 `cudaFreeHost` 在异常路径上的
等待保障。超出空闲容量或 drain 失败的缓冲区不进入缓存。
池与 CUDA backend 的生命周期保持正确顺序；共享和单请求执行器均接入，
因而后续 none/MTP/DFlash 对照必须同等开启，不能只给候选路径此优化。

## 当前验证

- 35 项主机 CTest 通过。新增池测试覆盖独占所有权、大小匹配、容量上限、
  drain 失败、池先销毁、并发复用；ASan/UBSan 通过。
- CUDA 测试特意延迟 H2D，在正常退出及异常展开后立即复用并覆写源缓冲区，
  128 个案例全部正确，compute-sanitizer memcheck 为零错误。
- C16 使用同一二进制，在两个独立进程中比较旧/新配置：128 个响应全部通过，
  完整文本和每个流式回调逐字节一致。每进程含两组正常请求和两组取消请求。
- C4 补充请求与外部取消另通过 64 个响应，guided query 和 refresh 各通过
  32 个响应。合计 **256 个响应**全部通过旧/新配置的完整文本、回调逐字节对照。
  最终清单位于 `q8_pooled_io_summary01.json`，保存两进程、四请求组和全部阶段耗时。

正常 C16 请求组的旧/新耗时为 41.2539/29.4196 秒与 40.0624/29.1089 秒，
延迟减少约 27%–29%。新配置初始化约 0.031 秒，结束请求约 1.44–1.72 秒；
剩余主要开销是串行请求预填充/检索回放和联合目标验证。

| 正常请求组 | 旧/新墙钟时间比：组 1 | 组 2 |
| --- | ---: | ---: |
| C16 冷查询 | 1.402 | 1.376 |
| C4 补充请求 | 1.367 | 1.435 |
| C4 中途刷新 | 1.330 | 1.435 |
| C4 引导查询 | 1.252 | 1.343 |

补充请求的一条 stdout 汇总被最终 scheduler stderr 日志插入；原始日志完整保留。
汇总脚本先提取独立的 scheduler 记录，再重组该 stdout 行，并按 request ID
检查每组完成数量、阶段总和及全部输出哈希。未剔除该请求组。

这些是短冷请求的受控诊断：每种配置仅一个进程，两次组内重复不构成三轮独立
性能验收。它们不证明 DFlash 已超过最强 MTP 基线，也不证明达到公开测试水平。
完整同策略基线、长历史/归档/有界 repository 的并发生命周期、质量矩阵、
正式独立测量与最终工作区集成仍未关闭。

可复现入口：`run_q8_pooled_io_validation.py --run-id <新ID> --scope main|lifecycle`、
`run_q8_controller_profile.py`、`run_q8_pooled_io_cuda.py`。
脚本位于 `benchmark/dflash2/`；已有 run ID 拒绝覆盖。CUDA lease 检查使用固定
输出名，重跑前应另存运行 ID，保留已有证据。
