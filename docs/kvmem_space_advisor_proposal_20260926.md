# 面向天基原生智能体的持久记忆与按需协同推理体系结构

2026-09-26｜CCF—中科天算极光基金指南建议讨论稿

主要对应方向：**4. 天基原生大模型与智能体；1. 太空超算体系结构。**

星间、星地分布式算力作为系统部署与验证环境，兼顾方向 2。本稿研究已有算力和链路之上的智能体运行时、记忆管理与协同调度。量化指标为预研讨论目标，须结合合作方平台、任务数据和基线摸底后确定。

## 建议摘要

面向天基智能体在有限算力、存储与能源条件下持续执行复杂任务的需求，研究持久推理记忆与按需协同推理相结合的体系结构。由星载常驻模型承担日常任务，利用分层 KV 记忆维持长期任务上下文；针对本地难以解决的问题，根据任务截止时间、通信可达性、节点负载与能源状态，向具备相应能力的星上或地面模型发送问题及精选证据，并对返回建议进行验证和记忆更新。重点突破任务重要性感知的记忆保留、证据预算约束下的异构模型协作、通信窗口感知的存算协同调度，以及中断条件下的任务状态恢复。形成支持长期任务连续运行的原型系统，在灾害观测任务协同和载荷异常辅助诊断场景中，评价任务质量、按时完成率、通信量和系统能耗，为有限星载资源提供可按需增强的智能服务能力。

## 一、应用场景

### 1. 主场景：跨过境周期的灾害观测与任务协同

以山火、洪灾等持续演化事件为对象，智能体跨多次过境维护观测历史、已确认事件、任务进展和后续观测需求。视觉处理和数值分析由相应专业模块提供结果，智能体负责结合历史证据进行任务推理和工具调用。

星载常驻模型依托持久记忆完成事件记录、历史检索、常规解释和任务推进。遇到证据冲突、复杂任务权衡或反复失败的问题时，形成带有时间、来源、约束和截止时间的求助请求，交由可达的星上增强节点或地面节点处理。返回建议经过证据核对、资源约束检查及规划工具验证后，纳入本地任务状态。

例如，连续两次观测对某区域是否发生灾害给出不同结论，且下一次有效观测窗口有限。本地智能体检索相关历史，向增强节点提交差异证据和可用资源；增强节点给出需要补充的观测或候选计划；本地工具检查计划的可执行性，并记录实际执行结果，供下一次过境复用。

通信不可用时，本地可独立完成的子任务继续推进；依赖远端结果的子任务按预设策略等待、采用可验证的降级方案或到期取消。迟到建议需要与当前任务版本和环境状态重新核对。

### 2. 验证场景：载荷长期运行与异常辅助诊断

持续积累遥测事件、软件日志、操作记录和历史处理效果，在异常发生时检索相似情况及其上下文。针对本地无法确定的原因或处理方案，按需调用增强节点进行分析，再通过诊断工具或仿真环境验证。

该场景用于检验低频关键事件保留、长间隔证据召回、错误建议拒绝和中断恢复能力。首期以载荷任务辅助决策及可验证的软件操作为验证对象。

## 二、研究必要性

### 1. 长期任务需要把历史推理成果转化为可复用状态

天基智能体需要关联跨任务、跨时间的观测与执行记录。活动上下文和设备内存有限，历史增长后需要在状态保留、摘要、检索和重新计算之间取舍。KVMem 提供复用已计算 KV 的技术基础；星载应用进一步要求把任务价值、保存成本、数据搬运能耗和未来使用需求纳入同一管理策略。

普通前缀缓存已经能够复用连续前缀。本项目重点检验历史超过活动窗口、调用冷历史、任务切换及中断恢复时，持久记忆带来的增量收益。

### 2. 常驻模型与共享增强模型可以形成能力互补

常驻模型的能力和资源消耗需要适配节点条件。共享增强节点可以为复杂子问题提供额外能力，但每次求助都占用通信、计算和等待时间。需要研究本地求解与远端求助的价值边界，以及不同证据量对建议有效性的影响。

系统允许增强能力由算力较充足的星上节点、具备专长的其他节点或地面节点提供。节点选择依据任务能力、可达性和资源状态；模型规模只作为能力描述的一部分。

### 3. 空间通信使协作具有时间约束和状态依赖

通信的可达时间、吞吐和往返等待会影响建议能否在任务截止前发挥作用。NASA 的 DTN 资料将间歇连接和存储转发作为空间网络需要处理的条件。本项目依托已有链路及可用的传输机制，研究其上的任务求助、异步返回和状态一致性。[NASA DTN 概述](https://www.nasa.gov/reference/delay-disruption-tolerant-networking-overview/)

### 4. 记忆与协同存在需要实验证明的相互作用

较好的本地记忆可能减少重复求助，也可能帮助生成更充分的远端证据；经验证的远端建议及执行结果可以成为后续任务的本地记忆。反过来，更多 KV 保留会增加存储和搬运成本，更多证据也会增加传输和远端推理成本。因此需要联合优化，而非分别最大化记忆容量或求助次数。

核心研究问题是：**在任务质量与截止时间约束下，如何联合决定保留哪些历史状态、何时调用哪一节点、传递哪些证据，使单位资源能够完成更多有效任务？**

## 三、研究内容

### 1. 面向长期任务的分层持久记忆

研究设备内存、主存和非易失存储之间的 KV 工作集管理，结合重要性、时效性、复用价值和重新计算成本设计保留策略。对低频关键异常设置显式保护与配额；记录保护集合超过容量时的处理行为。

建立两类相互关联的数据：模型相关的推理状态，以及带来源和时间的原始记录、结构化事件与工具结果。KV 用于本地计算复用，原始记录用于证据交换、核验和必要时重建。保留原始记录所需的容量和 I/O 一并计入预算。

为模型、KV 布局和任务状态维护版本身份。检查点覆盖 KV、混合模型的递归状态、任务进度和待处理协作请求。研究检查点频率、恢复代价和正常运行开销之间的权衡。

### 2. 证据预算约束下的按需协同推理

基于 ask_advisor 的交互模式，把求助组织为可独立处理的任务请求，包含问题、目标、约束、已尝试步骤、相关证据、状态版本与有效期。

研究结合工具验证失败、证据冲突、任务复杂度、历史求助效果的触发方法，评估模型自报置信度的校准性。联合选择求助节点和证据预算；证据不足时允许受预算约束的补充请求，其往返成本纳入评价。

跨模型交换采用文本、结构化事实和必要的数据片段，并保持来源可追溯。KV 直接复用限定在模型、布局及上下文语义兼容且经验证的路径中。对确实需要图像等多模态证据的任务，另行计入数据获取与传输成本。

返回建议由本地模型和任务工具核验，区分建议、已验证事实和实际执行结果，再更新记忆。建议复用带有适用条件和有效期，防止过期结论持续影响后续任务。

### 3. 通信窗口感知的存算协同调度

把记忆读取、证据准备、请求传输、增强节点排队与推理、结果返回、本地验证组织成具有截止时间和依赖关系的任务图。调度决策同时考虑模型能力、记忆所在位置、冷热状态、预计通信窗口、节点负载、能源与温度约束。

研究就地执行、远端求助、延迟处理及证据预取策略，避免只根据模型推理时间选择节点。能力目录、队列信息和通信预测自身的陈旧性与维护流量也纳入评估。

采用任务 ID、请求 ID、状态版本和持久化结果记录处理重复、迟到和中断。依托底层可用的存储转发或断点续传机制，研究结果查询、去重和恢复；明确结果未知时的行为及本地应用结果的一致性。

由此形成由多个常驻智能体和共享增强服务组成的任务级分布式推理系统。首期覆盖异构节点部署、服务选择、队列与状态管理、通信中断及端到端执行。

### 4. 原型集成与联合评价

部署星载侧常驻模型与 KVMem 运行时、增强节点模型服务和协作调度模块。结合合作方提供的代表性板卡、任务数据与链路条件进行半实物验证，并为后续在轨试验提供可裁剪软件和观测接口。

采用统一任务轨迹评价任务质量、按时完成率、系统能量消耗和通信量，分析可达性、历史长度、证据预算与节点配置改变时的适用边界。

## 四、技术指标与评价方法

下表为预研候选指标。前三项可作为原型功能目标；性能阈值需完成基线测量后冻结，同一指标不得混用不同任务或资源条件。

| 维度 | 建议目标或评价方式 |
| --- | --- |
| 原型规模 | 支持至少 3 个逻辑算力节点、至少 2 档模型能力和 2 类任务；至少一个节点在合作方提供或认可的代表性板卡上运行，其他节点可仿真 |
| 长期运行 | 在预先固定的 KV、索引和记录存储预算内，累计输入达到 KV 仓库容量的 10 倍以上；明确已保留、归档、删除的历史量 |
| 协作完整性 | 验证本地处理、远端求助、建议核验、记忆更新，以及断链、重启、重复和迟到结果的处理 |
| 任务质量 | 在相同任务集上报告任务成功率、关键证据召回率、错误建议采纳率及截止时间内完成率；候选质量容差为相对指定基线下降不超过 3 个百分点 |
| 通信效率 | 在满足质量容差的同一运行配置下，相对采用增量传输与前缀缓存的常规协作基线，候选目标为每任务总通信字节降低至少 50%；同时报告每成功任务字节数 |
| 能量效率 | 在相同质量约束下，候选目标为平均每成功任务能量消耗降低至少 20%；分别报告星载侧与可测系统边界的能量，包含检索、读写、通信和增强节点计算 |
| 中断与恢复 | 在明确故障模型、注入位置及样本数的实验中，报告任务恢复成功率、结果重复应用次数、恢复 p95 时间、状态回退量与正常运行开销 |

50% 通信和 20% 能量改进是用于判断技术潜力的候选目标，尚无当前实验支撑。若预实验不能同时满足质量要求，应据实调整目标并报告质量—时延—通信—能量曲线。无链路等待、队列等待、失败任务和重试成本均计入端到端统计；无法测量的远端能量应标为缺失或估计，并披露估计方法。

### 基线与消融

至少设置四组，在相同节点、模型集合、链路轨迹和任务输入下运行：

1. 本地模型，采用常规前缀缓存与滑动窗口／摘要／RAG 中经调优的适用方案。
2. 本地模型与 KVMem，量化长期记忆自身的作用。
3. 常规记忆方案与按需 Advisor，采用合理的路由、增量证据和前缀缓存，量化一般协作的作用。
4. KVMem 与 Advisor 联合系统，进一步消融证据选择、求助调度、建议复用和中断处理。

增加同一可达条件下的持续远端强模型方案作为能力与资源参照；理想全连接强模型结果只能作为能力参照，不能冒充实际可部署基线。报告运行时间、总能量、任务尝试数和成功数，避免通过少处理任务获得表面的资源改进。

固定任务的失败次数、工具检查结果及外部环境，并区分固定轨迹的系统开销实验与会随模型行为分叉的闭环任务实验。通过多次重复和置信区间评估增益；验证集覆盖低频关键历史、错误或不足的建议，以及建议过期等情形。

**KVMem 基础。** 当前项目具有分层 KV、按查询选择工作集、有界仓库管理和归档恢复等实现。4B 有界仓库和 27B 大规模归档的验证来自不同配置，分别支持相应能力；完整在线协作、归档与有界回收的联合路径需要重新集成验证。整个服务进程的临时内存、原始记录、增量请求协议和目标平台适配也需要单独审计。[有界仓库验收](/home/chaidi/qw3/docs/kvmem_bounded_repository_validation_20260917.md)、[归档状态](/home/chaidi/qw3/docs/kvmem_context_archive_status.md)

**SuperAdvisor 基础。** 已有按需问题与证据提交、建议返回和本地核验的交互流程，以及调用快照和结果持久化等实现；公开仓库记录了真实模型调用验收。当前尚无对照质量与成本基准，也未验证星间动态调度或容迟协作。上述增益和适配属于本项目拟研究内容。[项目说明](https://github.com/kvmem/dsh-super-advisor)、[实现说明](https://github.com/kvmem/dsh-super-advisor/blob/main/DESIGN.md)、[验收记录](https://github.com/kvmem/dsh-super-advisor/blob/main/ACCEPTANCE.md)

## 撰写和答辩时应突出的问题

### 与已有工作的关系

强弱模型路由已有 RouteLLM 等研究；星间协作也已有模型切分与中间激活交换方案。可据此将本项目的研究重点明确为：长期有状态任务中，记忆保留、证据传输、求助价值与通信时机的联合决策，以及异步返回后的任务连续性。[RouteLLM](https://arxiv.org/abs/2406.18665)、[星间协作推理研究](https://arxiv.org/abs/2604.04654)

三项可检验假设是：

- 持久记忆提高相关历史证据的可用性，在一定保留成本下减少重复计算和重复求助。
- 面向求助的证据选择，在给定字节预算下提高建议的有效性，并通过本地验证限制错误建议的影响。
- 联合考虑记忆位置、通信窗口和任务截止时间的调度，提高异构资源条件下的有效任务完成率。

### 对两个主方向的贡献

方向 4 的交付是能够持续积累、调用和更新任务记忆，并按需协同的天基智能体原型。方向 1 的交付是支撑该能力的状态分层、数据搬运、任务图执行和资源调度机制，以及可复查的性能与能耗测量。

### 合作方价值与实施顺序

为极光系列星载计算平台形成可部署的智能体运行软件、代表性任务负载和配置评估工具，使不同算力与存储配置的能力收益能够量化比较，并为共享增强节点的部署提供依据。

第一阶段确定目标板卡、模型与任务，完成基础移植及四组基线；第二阶段实现证据交换和联合调度，开展可控链路与中断实验；第三阶段在代表性硬件和真实任务数据上完成闭环验证，整理具备实施条件的在轨演示方案。阶段推进以可复查的任务与资源收益为依据。

### 对外说明用语

“通过持久记忆让星载智能体持续积累任务经验，通过按需协同让共享强模型能力在合适的时机服务复杂任务，并由存算调度把两者的资源开销控制在平台预算内。”
