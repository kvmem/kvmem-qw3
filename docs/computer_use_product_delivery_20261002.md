# 本地 Computer Use 产品交付路线

2026-10-02，按用户最新要求更新：目标是可真实使用的完整解决方案。模型诊断服务于
产品改进，不能以测试报告替代产品交付，也不能把等待整套评测完成作为不改进流程的理由。

## 当前产品方向

本地模型理解目标并维护任务状态；受控系统工具承担可确定执行的安装、环境、文件等
操作；GUI 工具承担界面交互。独立校验器检查结果，恢复控制器处理已知异常；冻结纯本地
基线后，DeepSeek V4.1 Flash 顾问处理确实需要更强判断的剩余困难。

尽可能在本地完成任务，顾问默认关闭并明确标识。工具可观测、可取消、有预算和明确的
目标范围。CLI/工具辅助、纯 GUI、顾问协助分别标注；不把借助结构化工具的成绩当作视觉
模型本身提升。所谓竞争力要从同条件的任务交付表现证明，不预先声称领先其他产品。

## 第一批真实产品任务

| ID | 用户目标和初始条件 | 独立验收 |
|---|---|---|
| product-python-new | 干净 Windows VM 中配置可用 Python 项目环境 | 明确解释器版本；创建项目 venv；安装指定依赖；项目脚本通过；新终端仍选中正确解释器；原有环境不被破坏 |
| product-python-repair | 已安装但解释器选择、PATH 或依赖不一致 | 先报告发现的冲突；仅修复目标项目；新进程重复运行通过；其他项目保持可用 |
| product-latex-new | 干净 VM 安装 LaTeX 并生成中文公式文档 | 来源和安装版本留证；命令可发现；指定源文件编译成功；PDF 内容和页面可检查；新进程可再次编译 |
| product-latex-repair | 固定制造缺失宏包或编译配置问题 | 正确定位失败；有限步骤内补齐或修复；使用同一原始文档成功编译；无无限重试 |

每类先做一个完整本地产品试次，保留失败，再针对首次错误修改。实例与版本冻结后
各做三次同条件验收，共 12 次产品试次。包下载采用固定版本/校验清单；缓存冷热、网络
时间、安装时间和模型等待分开记录，不把缓存差异当成 agent 改善。

第一版在 Windows 测试 VM 完成，随后再安排用户物理机和 Mac。安装来源、发行版、
版本、项目依赖和文档验收细则在开跑前固定，不由模型临时改变评分。不得用预装好的
最终环境替代从头安装任务；离线缓存若使用必须明确作为单独条件。

## 产品增量及完成条件

1. **基础可控性**：确认目标窗口/文档、限制无进展循环、保留暂停和不确定动作处理。
   当前正在执行 P0 固定操作；其发现直接用于第一轮通用修复。
2. **本地推理与视觉诊断**：完成 P1/P2，决定何时需要 thinking、局部图像放大、
   结构化状态。不能为了补提示而无界堆叠整段截图历史。
3. **系统配置能力**：新增显式的环境配置运行模式与受控工具。安装和配置命令有
   参数范围、过程输出、退出码、进程终止及核验步骤；不默默扩大现有办公模式权限。
   不能把任意未校验的模型 shell 字符串当作可靠解决方案。
4. **任务状态与交付**：将计划、已完成检查点、环境/文件事实和当前阻碍保存为
   可恢复状态；完成必须有独立成果校验。明确展示进行中、待处理问题、接管和实际完成。
5. **恢复**：区分慢加载、拒绝操作、焦点偏移、依赖错误和不确定投递；针对类别采取
   有界措施，无法解决时保留可恢复现场，避免纯观察空转。
6. **可选顾问**：选定任务的本地基线冻结后，实施 P7/P8。顾问只提供建议，由本地流程
   校验执行；其费用、上传范围、延迟和收益透明可查。
7. **回归与性能**：原 P3–P6、KVMem 开关及十场景继续作为专项/综合回归。缺失的
   OSWorld 外部材料单独追踪，不阻塞无依赖的产品工作或顾问工程准备。

## 执行节奏和竞争力衡量

每一轮都交付“真实任务 → 首个错误及证据 → 一到两项通用修改 → 同条件复测”。
优先修复影响任务完成的共同原因，再优化延迟与资源；不能只提高模型答题分数。
纯本地诊断仍先于顾问参与业务试验，但产品流程修复可以随证据逐步进入，不必等全部
样本完成。原来纯串行的排期据此调整，原任务和失败分母保留。

分别比较：当前本地 GUI 基线、加入受控系统工具和恢复的本地产品、可选顾问产品。
对于基线不支持的安装动作明确标注“不支持”，不能靠越权执行制造基线结果。
测量无人干预完成次数/总次数、重开会话后的可用性、错误恢复、总时延及拆分、接管
次数、资源峰值、顾问调用/费用和证据体积。所有结果提供版本、配置、失败样例与视频。

最终交付应包含能实际执行上述用户任务的应用、安装与运行说明、配置模板、可恢复的
任务状态、独立验收和回放页面。能力仍不足的任务要有明确边界与接管出口，不伪报成功。
