# KVMem 规则回收策略 v1

状态：设计，未实现。2026-09-05。按用户最新要求，第一版不训练判别模型，不要求换模型后重新采集训练集。采用硬保护、规则分级、组内热度排序和候选观察期。这里只定义选择策略；物理回收仍依赖[后台 GC 设计](/home/chaidi/qw3/docs/kvmem_background_gc_design.md)中的视图、lease、generation、空闲储备和 GPU index 一致性。

## 输出含义与原则

输出 `eligible, retention_score, reason_flags, evidence_epoch`。`retention_score` 越低越先考虑删除；它是确定性的保留优先级，不是未来复用概率，也不是预期损失。不能将分数 5 解释成 5% 风险，不能把整批分数相加当作误删概率。

先分级可以避免“很久没用”抵消“正在排查错误”这类重要证据。规则依赖实际使用、内容关系与相对检索排名，不依赖具体模型的 raw score 数值。跨模型仍需小规模质量/延迟验证，不承诺所有模型上同样有效。

## 一、先排除不可回收资源

已有安全协议判定以下对象 `eligible=false`，不通过任何评分解除保护：

- 当前工作集、正在构建的工作集和实际持有的 checkpoint 引用。
- 未封口 tail、必须保留的 sink/query 区间。
- 未结束的读写、capture、H2D/D2H 与其他资源 lease。
- 退休前无法确认 generation 或安全事件水位的资源。

第一版只处理已离开 GPU 的 sealed 冷 blocks。不能仅检查当前 `in_working_set` 字段：all-fit identity window、在途计划等也必须纳入安全协议。

## 二、分成五个保留等级

从上往下判断，取第一个匹配项；因此强保护覆盖重复/过时规则。各等级的范围不会重叠。

| 判断顺序 | 等级 L | 分数范围 | 条件 |
| --- | ---: | --- | --- |
| 1 | 4 | 80–99 | 已纳入有预算保护集合的回退前驱、未解决修改的旧片段、失败证据和必要基线 |
| 2 | 3 | 60–79 | 刚产生/刚被实际使用，近期已有高分或接近入选边界，或衰减使用频率仍高 |
| 3 | 0 | 0–19 | 整块来源可确认、内容重复，仍有可检索的替代观察；通过前两项后才可降级 |
| 4 | 1 | 20–39 | 整块旧观察已被验证后的新观察覆盖；或者在近期连续多次真实评分中位于低位、未选中且远离入选边界 |
| 5 | 2 | 40–59 | 其余可回收历史，包括评分缺失/陈旧、来源未知的普通冷 blocks |

“内容重复”和“新观察覆盖”需要满足：对象身份/版本关系可靠，实际返回内容覆盖整块有效信息，必要解释结构仍可用，并且替代观察本身保持 live。不能因为同一路径有了新 Read 就降级整个旧 message。相同文本在不同上下文下的 KV 不严格等价，因此即使 L=0 也仍是启发式候选。

对于 partial/mixed block，第一版不因部分内容被覆盖而使用 L=0/1 的内容降级规则；它仍可根据自己的使用/评分进入其他等级。任意 Bash、未知外部写入、截断或范围映射不清时，内容关系保持 unknown。

同一次回收事务先确定并保护替代观察，再选择依赖它的旧观察；替代者不得进入同批删除。替代关系和 generation 在提交前复核，防止所有重复副本被同时清掉。使用“新版本已验证”的规则时，验证必须来自可靠的工具包装层并注明覆盖范围；只确认写入成功或 shell 返回 0 不算通过测试。即使验证通过，也不证明旧内容永无用途。

## 三、同等级内的热度

最小实现复用衰减频率，不训练权重：

```text
H = 8 个有效 agent steps                 // 起始参数，未验证
age = t - max(birth_step, last_use_step) // 从未复用时使用 birth_step
R = 2^(-age / H)

f(t) = f(last_update) * 2^(-(t-last_update)/H)
实际使用一次：f += 1                    // 每个 agent step 最多一次
F = min(f(t) / 4, 1)

Q = 最近至多 3 次有效评分中 max(q_i * 2^(-(t-t_i)/H))
heat = max(R, F, Q)                      // 没有有效 Q 时只计算 max(R,F)
retention_score = 20 * L + 19 * heat
```

`q_i` 是当前 eligible 集合内的 Mean-K 相对百分位，范围 0–1，越高越相关。超过 H steps 的评分不再用于 Q，改为“评分陈旧”。去掉 Q 不等于把缺失解释为零相关：缺少有效评分时，禁止用“持续低分”规则进入 L=1；内容关系不明确时归入 L=2。

使用 max 是为了让任一种强的热度证据提高保留优先级，而不是被其他低值平均掉。等级顺序保证 L=4 的错误证据不会因年龄很大而排到普通冷历史之前。相同分数优先处理更久未用者；还相同时采用稳定历史 ID 排序，便于复现。

回收资源按实际可复用的 bytes/slots 计数；分数仍优先决定语义顺序。同等级且热度相近时可以优先选能凑齐目标资源的 blocks，但不将这一做法宣称为最优的成本/收益选择。共享 slab/chunk 的逻辑删除不等于立即得到对应物理字节。

## 四、Mean-K 的使用规则

仅消费现有 scorer 已回到 Host 的结果。在已有 score 数组进入下一次改写前，以明确的所有权/快照交给后台；不能异步读取 executor 正在修改的数组。相对排名在 CPU worker 计算，必要时有界分批，不在前台新增全量排序。

- 一次有效观测要求：真实的新 query/评分事件，block 确实在 eligible 集合内，score 类型有效。同一 agent step 的相关重放合并；它们最多贡献一次冷证据，任一高分则保留正证据。
- passthrough、all-fit、纯 pressure 裁剪、评分缺失和不兼容 fallback 不贡献低分次数。实际入选/使用仍按真实使用事件记热度。
- 同分使用平均名次百分位，不按 block ID 人为拆成冷热。空集合、无效数值和无区分度分数记为 unknown，不产生高分或低分证据。
- 起始规则：最近 H steps 内连续 3 次有效观测均处于后 20%，均未选中且不接近入选边界，才构成“持续低分”。无新评分不增加计数；评分历史过期或模型/scorer epoch 变化后重新积累。
- 正证据优先：近期处于前 20%，或处于实际语义 top-k 边界附近，进入 L=3。对支持的普通 block top-k，边界附近可先定义为排名距离不超过 eligible 数量的 5%；复杂 group/quota 需明确各自边界语义，不能照搬该数值。

百分位降低了 raw score 尺度变化的影响，但不会让不同模型的相关性质量完全一致。更换模型/scorer 时清空这段评分历史，沿用相同规则配置即可；已有 KV/index 自身的模型兼容性仍由系统保证。

现有 82 条实验中，23 条没有语义重选、26 条只有一次，因此 L=2 的通用冷历史回收是必要路径；不能让“必须有三次低分”成为所有回收的前提。

## 五、错误历史与新内容的保护边界

L=4 仅保护相关片段，不自动扩展到某个文件的所有版本。优先使用已有 Edit 中的 old/new、最近可回退的前驱和失败输出；GC 不生成摘要或新的 diff，也不要求模型额外 prefill。

显式验证通过、相关问题关闭或回退完成后，重新评估保护集合；若仍是必要基线/其他未解决问题的依赖则继续保留，否则退出 L=4。无法可靠判断的状态保持 unknown，不通过文本猜测“错误已经解决”。

保护集合使用独立字节预算，起始可以取 live 容量的 10%，需要包含实际 block 对齐和重叠去重。它是软预算，不是额外 lease：超出时先保留直接关联当前未解决操作、最近实际使用的片段，其余取消 L=4 特权并重新走普通规则。预算不足和因此发生的降级必须可观测，不能承诺保住每一个旧版本。无需因为未解决标志一直存在就无限占用空间。

L=3 的新内容/最近使用保护起始为 4 steps，热度频繁保护起始为 `f >= 2`，评分保护按最近 H steps 的有效高分判断。上述保护都是软保护；巨大首次 prefill 全部变成 Young 时，沿用总体 admission、grace 字节预算和压力降级规则，不能因此永远无法回收。

## 六、何时真正删除

无容量需求时不因为分数低就持续清空历史。后台根据 ready-slot 储备、已接纳 append 和各资源水位计算回收目标，按分数从低到高选择；正常优先 L=0/1/2，仅回收达到目标所需的量。

候选先保留检索资格，起始观察 2 个有效 agent steps；观察期本身不制造新的 Mean-K 低分证据。出现实际使用、高分、回退关联或替代者失效时取消/重新判定候选。规则依据、generation 或事件水位变化时提交前复核；不根据旧快照直接删除。

缺少新评分时，L=0/1 的内容依据或 L=2 的通用热度仍可使候选经过观察期进入回收，不无限等待下次 GPU scorer。无新 agent steps 时只经过 wall clock 也不增加冷证据；共享容量压力下的闲置会话处理需要单独的明确策略。

若低等级候选不足，按已有容量协议消耗 reserve，并仅在压力路径逐步放宽 L=3 软保护；L=4 先执行保护集合预算管理。每批有扫描、回收字节和 CPU 时间限额，记录最高触及等级。硬保护不可突破，储备无法覆盖已接纳负载时采用明确的 admission 行为，不让 decode 线程等待或接管 GC。

## 七、起始配置与验证

以下仅为一组可复现实验的起始值，不是当前轨迹拟合出的最优参数：

| 参数 | 起始值 |
| --- | --- |
| 热度半衰期 / score 新鲜窗口 H | 8 agent steps |
| 新增/最近使用 grace | 4 agent steps |
| 高、低相对分数区间 | 前 20% / 后 20% |
| 持续低分次数 | 3 次独立有效观测 |
| Candidate 观察期 | 2 agent steps |
| 回退/基线软保护预算 | live 容量的 10% |

至少检查以下规则不变量：

- 硬保护与当前真实引用优先于任何分数；重复但刚使用的内容归 L=3。
- 错误关联旧片段即使长期低分也先归 L=4；预算超出后的降级理由可见。
- 缺少评分不进入“持续低分”，相同分数不会产生任意冷热分组。
- 局部重读不触发整块内容覆盖；未知版本不触发 superseded；替代者和依赖者不同时删除。
- 在固定等级内，新增使用或提高有效 Q 不降低保留分数；过期评分不沿用冷观测资格。
- 跨模型/scorer 不混用评分历史；轨迹重放、物理搬运不产生虚假独立证据。

实施时先提供纯 CPU 的规则函数和可解释决策记录，再接入不实际删除的 shadow。记录候选 ID、等级、分数、理由、有效评分次数、观察期取消原因，以及后续实际复用；无需收集训练集或构建训练流程。按固定容量比较 LFU、LFU+Mean-K 规则、LFU+内容规则和联合规则，覆盖部分重读、回退和评分稀疏样本。

换模型时做小规模 shadow/质量回归即可检验是否需调整参数；相同来源任务/复用运行不可当作独立证据。真实 hard GC 前仍需端到端成功率、额外工具调用/prefill、TTFT/TBT 和资源隔离验证。规则设计只保证决策可解释，不保证未来逐 block 最优，也没有零延迟增量的实测结论。
