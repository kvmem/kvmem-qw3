# Windows 复杂任务：KVMem 开关对比方案

状态：**评估设计与已有证据回放样例已完成；以下复杂任务和连续录屏尚未执行。**
继续使用 Codex app-server、QW3 和现有 Windows VM。主实验固定 DFlash2，
只比较两套明确记录的 KVMem 开启/关闭配置；MTP、无推测解码作为单独控制组。
不再以 48GB 为显存上限。模型暂在当前 Linux GPU 宿主机运行，不能将结果
表述为普通 Windows 电脑上的本机推理性能。

## 需要回答的问题

1. 相同截止时间内，能否独立、正确完成更多真实工作？
2. 用户从提交到第一次有效操作、每一步等待、最终交付分别需要多久？
3. 随着历史积累，是否仍能用对早期信息，并正确处理后来的修订？
4. 得到这些结果需要多少显存、内存、操作和人工干预？

不预设 KVMem 在每项指标上都更好。已有同输入、禁用前缀复用的长请求中，
开启侧显存更低，但冷推理更慢；真实多轮任务则包含历史复用收益。
必须同时报告任务结果与引擎分解，不能用 token/s 代替产品效果。

## 指标及计算口径

| 层面 | 主要指标 | 口径 |
| --- | --- | --- |
| 完成效果 | 无人工干预的严格成功率 | 全部必需成果正确且无禁止副作用，才算成功；分母包含所有有效试验的超时、OOM、错误和主动放弃 |
| 交付速度 | 提交至独立验证成功的总时长 | 展示截止时间内成功率曲线；超时是未完成，不能当作在截止时刻完成，也不能从总表删掉 |
| 阶段效果 | 各里程碑通过率、必需字段准确率 | 补充解释失败发生在哪里，不替代严格任务成功率 |
| 初始体验 | 提交→第一个有效动作；冷启动→可用 | 分别报告任务交互和模型/应用启动，不把启动时间偷偷移出用户等待时间 |
| 逐步等待 | 观测→下一动作发起、动作发起→执行后观测 | P50/P95 和按任务分布；现有观测入库时间只是截图时刻的代理值，新增采集应记录实际时间 |
| 卡顿 | >5s、>15s、>60s 的等待次数和总时长 | 区分推理、工具、应用加载和重试；保留被取消、无终止时间的请求及其已等待时长 |
| 行为效率 | 无效/拒绝/过期动作、重复操作、无进展循环、返工次数 | 结合业务里程碑判定；操作多不自动等于低质量，不强迫走唯一参考路径 |
| 历史质量 | 早期事实准确率、修订采用率、过期信息误用率 | 明确事实最初出现位置、修订里程碑和最终使用位置；不能只测随机验证码 |
| 接管与恢复 | 人工接管次数、暂停/取消延迟、恢复成功率 | 无人工辅助和有辅助结果分开；核对暂停后无多余动作、恢复后无重复业务提交 |
| 资源 | 采样显存峰值、引擎 RSS、客户端 RAM/CPU | 标注采样间隔和范围；Windows 客户端用 PID+创建时间身份校验；设备峰值不等于最低可运行显存 |
| 引擎归因 | TTFT、prefill、decode、前缀复用率/重算量、检索状态、DFlash 接受率 | TTFT 不等于第一个有效桌面动作；记录 fallback，不能把退化执行记为指定策略成功运行 |

若采集功耗，可积分得到设备 GPU 能耗，并报告采样周期及空闲基线；不能称为整机能耗。
界面可用性的补充评审可把策略标签隐藏后，让评审看相同任务的完整回放，
记录“等待是否可理解、是否需接管、失败是否能恢复”，不能代替客观判分。

按真实输入 token 数分组：<32K、32–128K、128–256K、256–512K。
它们是分析分层，不强行给某侧填充冗余截图。报告每组实际样本数；达不到某长度
或先 OOM 本身是结果。短任务仍保留，检查额外开销及质量回退。

## 三种比较，分别回答不同问题

### A. 完整产品配置的任务对比（主实验）

同一模型、量化、解码方式、分辨率、应用版本、任务素材、初始快照、工具上限和
截止时间。开启侧采用已验证的 KVMem、guided refresh 与历史复用配置；关闭侧
采用已明确记录的 dense 配置。记录所有生效参数和代码/二进制/模型哈希。

两侧自由执行同一工作流，允许产生不同动作。当前关闭侧没有等价的 dense
前缀复用实现，因此结论是“这两套完整配置的产品收益”，不是纯稀疏检索加速比。

### B. 相同输入的引擎比较（解释原因）

从开启和关闭两侧轨迹共同抽样，冻结消息、截图、工具定义和生成参数；双方
禁用跨请求前缀复用。相同输入分别运行 on/off，测 prefill、TTFT、decode、显存，
同时核对下一动作/答案质量。不能只选开启侧的成功轨迹作为所有输入来源。

保存早期信息引用、修订覆盖和“替换历史图片后答案也应改变”的负控制。
guided refresh 配置必须显式记录；已有 guided-off 的同轮质量失败不能被隐藏。
这是推理请求评估，不计为完成了桌面任务。

### C. 前缀复用消融（区分收益来源）

在 KVMem 开启且 guided 配置相同的前提下，对固定、有序请求链分别启用/禁用
prefix reuse。后续请求使用冻结输入，不能把某侧新生成答案拼回去改变输入。
报告复用命中、重算 tokens、长尾等待及正确性。当前不能宣称已具备 dense warm
prefix 的公平基线；若后续实现，另补第四组。

## 试验规模与控制

- 预跑只用于修复任务、判分器、采集和合理预算，保留所有失败；正式计分前冻结版本。
- 首轮：10 个不同场景 × 2 种配置 = **20 次运行（10 对）**。
  这是探索性结果，不足以证明高可靠性或稳定的 P95。
- 重复：每个场景每侧总计 3 次，即 **60 次运行（30 对）**；未改版本时包含首轮。
  将来如增加随机化业务实例，独立冻结素材和答案，不与这 10 个原始场景混算。
- 每一对使用相同实例/种子；使用预先打乱且均衡的 AB/BA 顺序。两侧在同一 GPU
  上串行运行，每轮恢复快照；不能同时争抢显卡。记录其他进程和资源干扰。
- 冷/热缓存策略固定；应用和模型版本、系统更新、屏幕缩放、语言、登录状态保持一致。
- 目前 native suite 遇到首个任务失败会停止；新计分调度器需要继续普通质量失败/
  超时以维持分母，身份不符、快照失败等基础设施错误才中止并单独记录。
- 基础设施失败保留原记录，修复后对整对重跑；不可把模型 OOM、卡死或错误操作
  事后改称基础设施错误。每次运行都保留其实际策略和原因。
- 报告逐任务成功率、差值和配对分布；两侧均成功的配对可报告时间比，并注明条件。
  不把超时侧的截止时间除以成功时长称为完成加速比。
- 正式置信区间以业务实例为单位分组/重采样，重复试验不当作不同任务；
  不能把同一任务的数千动作当作数千独立成功率样本。先报告每族，防止平均值掩盖回退。

## 录屏与回放

### 后续连续录屏的实现约定

1. 使用宿主机只读 VNC 采集，复用 shared-client 协议，不发送鼠标键盘。
   **不额外调用桌面 `/observe` 录屏**，该操作会更换观测标识、影响模型动作有效性。
2. 固定 1280×800，初始选择 10fps；两侧相同采集和 CPU 编码参数。
   先用固定轨迹测录制开销，再冻结参数，避免编码挤占推理 GPU。
3. 从任务提交前开始，到最终结果验证或失败清理后停止，保留等待、错误和重试。
   先保留可在异常退出后恢复的原始容器，正常结束后再生成 MP4。
4. 宿主机统一单调时钟记录提交、视频帧、推理、动作、验证事件；若事件来自
   Windows 客户端，建立有误差范围的时钟映射。不得直接混用来宾机墙上时间。
5. 输出 on/off 原始视频、同墙钟双栏视频、events.jsonl、metrics.csv、判分结果、
   最终文件和哈希清单。保存帧丢失、重复帧/编码延迟信息。
6. 双栏主视图从各自任务提交对齐，同速播放；已完成一侧停留并显示完成时间，
   超时侧保留整个截止过程。可提供明确标注的 4×预览，保留 1×原片。
7. 另提供按业务里程碑对齐的行为回放，但标明时间被重新对齐，不能用于速度结论。
   加书签定位 >15s 卡顿、错误/返工、128K 边界、规则修订和结束原因。

### 本次已交付的观测帧回放

构建工具：[scripts/computer_use_replay.py](../scripts/computer_use_replay.py)。
只读已结束的 archive run，不连接桌面或模型。验证数据库、输入、截图及引擎身份，
输出可离线打开的双栏 HTML、完整时间轴和来源清单；支持拖动、1×/4×/16×。
无观测的时间保持上一帧，**不能据此判断桌面当时没有变化**。

```sh
.venv/bin/python scripts/computer_use_replay.py \
  --on apps/computer_use/.runtime/windows-long-on-07 \
  --off apps/computer_use/.runtime/windows-long-off-07 \
  --output apps/computer_use/.runtime/comparison-replay-long-07-NEW
```

已生成样例位于 `apps/computer_use/.runtime/comparison-replay-long-07-04/index.html`。
每侧以自身保存的 task.started_at 为零点，只使用宿主客户端记录，不混用来宾时间。
截图时间为入库时间。末尾清理观测可能稍晚于报告 elapsed，时间轴保留该观测；
显示的任务耗时仍为原始结果值。动作最终状态明确标注为最终日志状态，不能当作
该动作刚发起时已经执行完成。

这个历史任务开启侧 416.09s 完成 36 页，关闭侧达到 900s 截止，901.09s 含停止
开销，停在第 18 页，无结果文件。它只有一对且轨迹不同，不能推出整体可靠性
或纯检索加速比。关闭侧还在中间消息转抄了本任务禁止转抄的引用，保留该违规。
完整身份和既有结果见[验收索引](computer_use_acceptance_20261001.md)。
