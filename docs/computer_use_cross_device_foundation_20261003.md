# 跨设备框架基础阶段记录

这是活动目标的阶段记录，不是框架完成报告，也不是新 OSWorld 成功率。计划见 `computer_use_cross_device_goal_20261003.md`，逐次状态见对应 progress JSON。

## 已实现

- 共享任务执行核心：持久步骤、声明的可观察条件、20 秒内工具轮询、跨 action_id 的重复输入意图检测、完成条件与输入送达分离。未知送达仍保留并暂停，不重新发送。
- 设备身份、会话、显示尺寸与能力协议。Windows 沿用原执行器；Linux 网关复用官方 OSWorld PyAutoGUI/AT-SPI；Android 网关复用 Appium 3.8.0 / UiAutomator2 8.7.0。
- 设备注册表和 UI 选择入口。当前只允许本机网关；运行/暂停任务不能切换设备。切换会归档原任务，重启该应用拥有的 Codex 工具配置，设备账本分开存储。
- 显存共用启动选项：保留本任务引擎锁，检查可用显存并记录启动时其他 PID；不获取其他长测试的独占锁，不终止外部进程。正式性能对照仍须记录运行期间外部负载。
- 模型请求改用新连接，避免桌面观察耗时接近后端空闲连接寿命时的连接中断。对两次请求使用不同连接已有合约检查。
- 验证完成条件后由框架直接暂停输入并结束任务，再中断剩余模型收尾；不需要另一轮生成结束语。已验证的完成记录不会被这一中断改为失败。环境配置任务仍须通过原软件工具检查。
- verified 模式的动作格式明确要求内联步骤条件；控件信息对模型仅精简重复字段，保留原始截图、控件 ID、位置、不同于标签的值、未选中状态与完整性标记。执行器保存完整原始证据。
- verified 模式要求视觉估计使用明确的 0–1000 归一化坐标，由驱动按当前截图尺寸转换；系统控件仍优先使用。错误坐标格式在发送输入前拒绝，保留原错误记录。
- 自动读取本地后端实际上下文容量，生成对应 Codex 配置并绑定任务检查点，避免引擎调整后沿用错误容量。

## 正式对照执行约束

使用 osworld_linux.campaign 先冻结共享框架和宿主评估工具，再交错执行十场景、两流程、各两次，共40次。每次新建官方 Linux VM，原始磁盘只读，不复用答案资格虚拟机；连续视频在独立评分前结束。初始化最长900秒、独立评分最长600秒，整体看门狗中断只处理本次子进程；缺少终止记录时先核对，不自动重发或启动下一台 VM。

035 的原始云端评分保持不可用。本地工作簿评分使用已保存值，不强制重算，也不向 agent 提供规则或标准答案；其正负控制在官方评估依赖环境下为0/1。原始空白工作簿缺少可选 dimension 字段，已修复本地评分读取并单独验证。原失败仍保留，不把读取异常返回的0当成有效负控制。定时消息的原始延迟保持不变，末尾另外检查消息是否全部送达。

## 多字段任务与独立验收探针

`platform_pilots.py`支持六类：Android设置、联系人、浏览器，Linux文本、浏览器、Calc。新浏览器和Calc任务默认900秒，联系人600秒；既有设置180秒和文本360秒保持原预算。可明确设置60–1800秒，预算写入每次新目录；不同预算不能称为同条件改善。

浏览器用同一份离线六字段表单，填写、预览、最终保存分开。服务只在设备容器/虚拟机回环地址监听，不提供评分规则或读状态API；独立读已保存字段，要求只有一次最终提交。Linux真实界面正负资格核验通过（browser-fixture-qualification-03）；Android容器存储0/1及真实初始表单呈现通过（browser-fixture-qualification-04），后者尚不是完整Android GUI填写通过。前三次Android资格记录的`passed`仅反映存储范围，已保留原记录并加scope-correction说明，不能作为浏览器环境就绪证据。

Android原先未连接模拟器自带AndroidWifi，Chrome首次启动界面也未完成。只在隔离测试模拟器选择无账户使用、拒绝通知初始化并连接虚拟网络；初始化操作与前后网络状态保留于browser-network-initialization-20261004。这不是模型操作成绩，也未修改宿主网络。

Calc创建唯一命名的工作簿，修改两个数值和另一张工作表的求和范围，保留其余非空单元格及公式。真实界面保存正对照通过（calc-fixture-qualification-01），两处缓存总额均500。评分不接受把公式替换成相同数值；缺缓存只单列，不伪称已重算。

同标题Chrome窗口暴露前台匹配缺陷。原始AT-SPI树有唯一active标记，候选仅在该标记唯一时选定窗口，无唯一标记仍返回unmatched；真实Linux表单复测通过。当前加载多个后台应用的Calc场景，整桌面读取超过4秒期限而无控件。候选已接入复用官方遍历函数的活动窗口读取，三次真实Calc捕获均成功，读取3.54–3.72秒。保留4秒客端读取期限并增加同样的服务端超时，读取失败仍返回截图和诚实状态；未证明其他界面的通用提速。

探针先保留业务核验，再收集录像。录像故障不会丢掉已保存的业务分数，但accepted仍要求业务通过、框架完成、无不确定动作和视频收集通过。21项针对性检查通过，覆盖重复提交、错误字段、误改其他单元格、公式替换、录像失败保留业务结果及容器被替换时禁止清理信号。这些均不计入真实模型成功率。

运行探针使用官方OSWorld Python依赖；实时Android视频另加入私有media-qualification的PyAV依赖路径。每次指定新output目录、实际app runtime和设备入口。真实模型探针与正式对照串行，资格测试不占用模型槽。服务停止前重新核对容器身份和精确进程参数；旧测试文件保留。
