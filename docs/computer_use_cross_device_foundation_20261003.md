# 跨设备框架基础阶段记录

这是活动目标的阶段记录，不是框架完成报告，也不是新 OSWorld 成功率。计划见 `computer_use_cross_device_goal_20261003.md`，逐次状态见对应 progress JSON。

## 已实现

- 共享任务执行核心：持久步骤、声明的可观察条件、20 秒内工具轮询、跨 action_id 的重复输入意图检测、完成条件与输入送达分离。未知送达仍保留并暂停，不重新发送。
- 设备身份、会话、显示尺寸与能力协议。Windows 沿用原执行器；Linux 网关复用官方 OSWorld PyAutoGUI/AT-SPI；Android 网关复用 Appium 3.8.0 / UiAutomator2 8.7.0。
- 设备注册表和 UI 选择入口。当前只允许本机网关；运行/暂停任务不能切换设备。切换会归档原任务，重启该应用拥有的 Codex 工具配置，设备账本分开存储。
- 显存共用启动选项：保留本任务引擎锁，检查可用显存并记录启动时其他 PID；不获取其他长测试的独占锁，不终止外部进程。正式性能对照仍须记录运行期间外部负载。
- 模型请求改用新连接，避免桌面观察耗时接近后端空闲连接寿命时的连接中断。对两次请求使用不同连接已有合约检查。
- 验证完成条件后由框架直接暂停输入并结束任务，再中断剩余模型收尾；不需要另一轮生成结束语。已验证的完成记录不会被这一中断改为失败。环境配置任务仍须通过原软件工具检查。
- verified 模式的动作格式明确要求内联步骤条件；控件信息对模型仅精简重复字段，保留原始截图、控件 ID、位置、不同于标签的值、未选中状态与完整性标记。执行器保存完整原始证据。
- verified 模式要求视觉估计使用明确的 0–1000 归一化坐标，由驱动按当前截图尺寸转换；系统控件仍优先使用。错误坐标格式在发送输入前拒绝，保留原错误记录。
- 自动读取本地后端实际上下文容量，生成对应 Codex 配置并绑定任务检查点，避免引擎调整后沿用错误容量。

## 已发现的问题与证据

Linux pilot01 的剪贴板后台所有者继承了桌面服务捕获的 stdout/stderr。文字已到编辑器，HTTP 回执却超时。记录和连续录像保留；改为将这些句柄明确指向空设备。独立复查英文、中文和换行输入，两个动作都拿到完整回执，控件值包含完整文本，未留下未知动作。

Linux pilot02 保存了文件，但字节比要求多一个末尾换行，随后模型请求连接中断。结束后独立检查确认精确内容不通过，因此不计成功。失败的 21,076,366 字节模型请求使用新连接重放获得 HTTP 200，且返回的工具没有被执行。这支持连接复用诊断；完整任务复测仍待完成。编辑器显示内容与实际保存字节的差别，说明业务验收不能仅依赖屏幕标题和可见文本。

Android 官方工具 SHA256 已校验，Android 35 Google APIs x86_64 revision 9、Emulator 37.2.12、platform-tools 37.0.1 已安装。宿主用户不能直接访问 KVM，使用项目容器的最小设备权限；SDK、Java、Node 与 Appium 依赖只读，只有 AVD 与模拟器数据可写，本机只开放 Appium 端口。初始 host 网络/宽挂载方案被自动审批拒绝，已改为桥接网络和收窄挂载。

Android 网关已通过打开设置并获取回执的检查。Appium 使用控件类名作为 XML 标签，原先按原始 UiAutomator 的 `<node>` 解析会得到零控件；修复后设置页读到 51 个控件。

## 验证边界

步骤条件证明的是 agent 声明的可见条件，并不证明它完整理解了用户目标。无进度指纹仍包含图像变化，动画/光标可能影响重复意图判断。Linux 使用 X11，不宣称已支持 Wayland；Android 只接明确选择的模拟器；macOS/iOS 尚未实现。普通模型推理、驱动合约、真实任务、官方独立评分必须分开计数。

正式 Linux OSWorld 已完成013、004各一对，四次独立评分均为0，尚无成功率改善证据。013、004、006、010、038、022、043、080、051 已通过原始评分器的 0/1 正负对照，答案不会进入模型任务虚拟机。006 只检查文件名；043 的原文约束有冲突；080 官方 Perfect 文件缺少部分评分要求，正对照使用已修复的宿主资格夹具。035 的网站动态消息初始化已修复，原始云端评分关闭，本地指标单列。下一阶段完成基础集成复测和三平台资格检查，冻结运行代码、任务初态与配置，进行原定十场景对照；所有预检失败和试验中断均保留。

## 正式对照执行约束

使用 osworld_linux.campaign 先冻结共享框架和宿主评估工具，再交错执行十场景、两流程、各两次，共40次。每次新建官方 Linux VM，原始磁盘只读，不复用答案资格虚拟机；连续视频在独立评分前结束。初始化最长900秒、独立评分最长600秒，整体看门狗中断只处理本次子进程；缺少终止记录时先核对，不自动重发或启动下一台 VM。

035 的原始云端评分保持不可用。本地工作簿评分使用已保存值，不强制重算，也不向 agent 提供规则或标准答案；其正负控制在官方评估依赖环境下为0/1。原始空白工作簿缺少可选 dimension 字段，已修复本地评分读取并单独验证。原失败仍保留，不把读取异常返回的0当成有效负控制。定时消息的原始延迟保持不变，末尾另外检查消息是否全部送达。

## 首轮结果驱动的后续候选

冻结版本9fe52d3继续运行40次对照；新的优化不进入这一版本。013旧流程在694.60秒、17次调用后暂停，多次遭遇60秒观察过期；新流程在122.46秒、6次调用后因组合分配推理耗尽4096输出token而失败。早失败的耗时不能计作速度改善。004两流程也均为0。所有连续视频和原始评分保留。

后续候选将单次总输出预算设为可配置并绑定任务检查点（默认仍4096，独立候选UI09为16384）。过期观察先重新捕获；只有设备相同且完整截图、前景、控件证据相同，或动作是明确白名单应用启动意图，才发送一次输入。界面变化返回新观察，保持零输入；不能通过增加时间阈值盲目操作。相关回归124项、121通过、3跳过；官方评估环境补充6项通过；实际Linux Codex链路3项通过；Windows client37原生181项通过，均不能作为真实模型任务通过率。
