# 单请求 KVMem：Q8 投影权重读取优化

本轮继续 Q8_0 主模型权重＋E4M3 FP8 目标 KV、单请求 KVMem。未开启多并发，
未新增 BF16 主模型权重或目标 KV 支持；官方 BF16 草稿与已有内部算术保持原样。

## 修改与适用范围

`src/mmvq_q8.cu` 的多输出投影内核增加默认关闭的 `QW3_Q8_FANOUT_LOAD_MODE`：
0 为原路径，1 为普通对齐 int32 读取，2 为 streaming int32 读取。
只在输入列数 5120、验证批宽 8 时进入新分支。该尺寸的权重行距 5440 字节、
scale 平面 320 字节，满足 int32 对齐。将两次 16 位读取和拼接替换为一次
32 位读取，并显式在八个 token 间复用权重。整数点积分组、FP32 累加顺序、
四 warp 归约保持不变。其他尺寸和默认配置保留原路径。

## 独立算子与正确性

用真实 DeltaNet 投影行数 [10240,6144,48,48] 和 attention 投影行数
[12288,1024,1024] 测试。分别轮换 358,604,800 和 311,951,360 字节权重，
均超过两倍 134,217,728 字节 L2。每种形状在一个进程内做九组轮换顺序的
原路径／普通 int32／streaming int32 测试；计时包含调用与量化，不是纯 kernel 时间。

streaming 模式的配对速度比分别为 **1.19547、1.16822**；普通 int32 为
1.16257、1.10602。streaming 寄存器从 40 增至 56，stack/local 为 0。
这些是独立算子结果，不能扩大为整模型收益。

两种新模式分别通过 CUDA memcheck：91 个通用 linear 算例，加六个八行、多输出、
含带填充输入的 fanout 算例，零错误。真实投影形状另在 benchmark 中检查了输出和保护区。
实际模型 build14 通过 4K 历史下的残差、完整词表 logits 检查，max-abs=0、argmax 差异 0。
上述数值检查不区分正负零，不扩大为所有浮点位模式一致。

## 整模型结果

同一 build14、4K 工程日志、KVMem W1024、T1/k20/p.95、256 输出，
两边均开启已有 SwiGLU reuse、FFN down streaming/int32，仅切换新 fanout 0/2。
三组独立进程对顺序为 off/on、on/off、off/on，每个进程取三个 GPU warm 样本中位数。

| 组 | 关闭 tok/s | 开启 tok/s | 速度比 |
| --- | ---: | ---: | ---: |
| 1 | 121.130 | 123.272 | 1.01768 |
| 2 | 120.751 | 123.246 | 1.02066 |
| 3 | 121.008 | 123.365 | 1.01948 |

配对几何均值 **1.01928（+1.93%）**。
同路线 CPU/GPU 输出检查通过；这是 DFlash 内核优化的工程用例结果，
不是 DFlash 与 MTP 或公开实现的正式对照。

五类公开任务各八个测量请求及一个预热，共 45 个完整响应，与上一 int32 配置的
choices、usage、seed、结束原因均一致。此项通过输出回归检查，不自动取得完整任务质量资格。

| 任务 | 测量请求 | 完整任务窗口 tok/s |
| --- | ---: | ---: |
| gsm8k | 8 | 161.702 |
| math500 | 8 | 143.952 |
| humaneval | 8 | 124.545 |
| mbpp | 8 | 126.310 |
| mt-bench | 8 | 116.094 |

这些是每任务八条的小样本结果，不能替换上一轮完整 GSM128 的 135.54 tok/s，
也不能作为公开达标证据。MBPP strict 接口与 MT-Bench judge 等质量问题仍待完成。

新选用模式为 2，默认仍为 0。当前改动尚未集成到主工作区。完整任务、独立重复、
剩余长历史生命周期及冻结矩阵、同机公开参考资格仍未全部完成；目标保持 active，
多并发继续后置。阶段 6 中参考端 greedy 和采样差异的失败记录保持不变。
