# 单请求 KVMem：候选完整 GSM128 验证

继续使用 Qwen3.8-27B Q8_0 主模型、E4M3 FP8 目标 KV、官方 DFlash2 草稿，
单请求 KVMem all-fit W8192/gen4096，T=1、k=20、p=.95、top-k-first，
冻结 xhigh 输入，最多输出 4096 token。没有开启多并发。

本轮完整 128 题产生 **65,127 token**，任务总耗时
**480.513 s**，吞吐 **135.536 tok/s**。
计时包含测量请求的准备、HTTP 往返和客户端处理，排除模型加载与预热；
计时期间没有编译、评分或其他 GPU 作业。

128 个测量响应及 1 个预热响应的完整 choices、usage、seed、结束原因，均与前一版
完整 GSM 记录一致。全部测量答案另逐一匹配既有评分记录的 SHA-256，因此可以沿用
该评分：**119/128**，保留 **4** 个 length 截断。
只取 `</think>` 后最终答案；没有重新运行评分器，也没有把 thinking 中出现正确数字
当作最终回答正确。此成绩仍是单任务质量诊断，不是完整非劣验收。

源码与 build13 二进制沿用阶段 5：SwiGLU reuse、FFN down streaming 和对齐 int32
读取均开启，草稿宽度 7。运行时源码没有在本轮新增修改。两个 streaming 开关仍默认关闭。
阶段 5 的三组独立进程对已给出 int32 子优化 +1.06% 的工程证据。

旧版完整 GSM 吞吐为 132.823 tok/s，本轮与它的历史比值为
**1.02043**。两次完整任务使用不同二进制且没有交替重复，
这个比值不能替代同一构建的消融或正式性能结论，也不能用于声称已追平 H200 公开结果。

同机公开实现方面，本轮实际验证了 vLLM Q8/FP8 none 与 DFlash 的五任务短 greedy，
以及 GPU 采样过滤分布。参考 greedy 只有 1/10 个独立输入完全一致；24 个采样分布
用例有 10 个不同。详细见 [参考资格报告](dflash2_c1_reference_qualification_20260925.md)。
因此该参考配置不进入正式性能比较，不修改原生采样规则或放宽标准来迁就它。

剩余工作仍包括统一候选构建后的完整任务和独立重复、全部质量资格、剩余 KVMem
生命周期与冻结矩阵、同机公开实现资格及最终集成。单请求通过后才继续多并发。
目标保持 active；本报告只关闭本轮有限范围验证。

原始证据与哈希见 `benchmark/dflash2/q8_c1_optimization_stage06.json`，完整请求、
服务日志与计时见 `q8_c1_public_int32_gsm_full01*`；输出逐题检查与评分继承依据见
`q8_c1_public_int32_gsm_full_summary01.json`。
