下一步顺序：

1. 关闭代理直连下载并对照官方 SHA-256；在独立 VM 状态核对版本、帮助和安装 dry run。
2. 先确定最小可用安装集合，冻结包仓库元数据及所需包文件哈希。记录冷下载和缓存条件，
   不把完整发行版预装到“新安装”试次的初始状态。
3. 固定一份含中文、标题和数学公式的用户源文件。选定可分发或系统已有的字体并记录
   具体身份；验证 XeLaTeX 产物文本、页数、视觉渲染及新进程再次编译。保持源文件不变。
4. 增加受控安装/编译工具、作业取消和错误分类。缺包恢复从编译错误定位包名，
   只安装固定清单中的包，再编译同一文件；限定次数，保留每次错误输出。
5. 完成一个本地模型产品试次，分析首个失败后再冻结三次正式验收。另建缺包初始状态，
   按相同方式完成修复场景。截图和 PDF 文件均交给独立验收器检查。

官方包工具支持查询、安装和完整性校验，可作为缺包处理的底层接口。
来源：[官方包管理说明](https://docs.miktex.org/manual/miktex-packages.html)。
具体安装参数、包集合、字体和编译命令须在开发实测后冻结，当前未把文档支持写成产品通过。
