# DFlash 2 / KVMem 长历史 C4 首轮优化对照

2026-09-27。结论：**轮转 prefill＋宽 Q8/SwiGLU 没有产生端到端吞吐提升**。
输出停顿明显减少，但等待主要移到了首 token 之前，因此不保留“输出窗口吞吐上涨”
作为整体加速结论。实验开关继续默认关闭。

## 范围与证据

`integrated_concurrency02` 完成必要检查后，在独占 RTX PRO 6000 GPU 上执行两个独立
进程：相同的 Quill/Effect 四条真实 DeepSWE 历史（131,310–134,067 token）、seed1000、
Q8_0 目标权重、FP8 KV、每请求 K131072/G65536。自然 EOS，输出上限4096。
两侧均开启修复后的固定 FP8 ragged attention，且不启用历史缓存、联合草稿及私有
query 让出。参考侧关闭独立 prefill 和宽 Q8；候选侧开启轮转 prefill、宽 Q8 和 SwiGLU。

原始命令、二进制及模型身份在 `benchmark/dflash2/integrated_concurrency02/plan.json`
和 `manifest.json`；逐请求输出、计时、验证批次和资源样本均保留。分析汇总为
`pair_analysis.json`。两组没有外来 GPU 进程或资源观察错误。

必要检查：prefill 刷新 C4 的32条响应、宽 SwiGLU C4 的32条响应分别通过开关前后
逐回调一致性；21个宽 SwiGLU 算子用例逐位一致、边界哨兵通过。

## 同输出工作量结果

四条请求分别输出1322、129、502、123 token，两组共2076 token，**完整 token ID 一致**。

| 指标 | 参考 | 轮转 prefill＋宽验证 |
|---|---:|---:|
| 请求组完成时间，秒 | 229.755 | 230.441 |
| 含长历史处理的冷服务吞吐，tok/s | 9.036 | 9.009 |
| 首次至末次回调共同窗口吞吐，tok/s | 11.479 | 55.930 |
| TTFT 中位数，秒 | 126.569 | 197.394 |
| 最长输出停顿，秒 | 150.501 | 3.562 |
| 草稿接受率 | 31.7246% | 31.7246% |
| 采样整卡显存峰值，十进制 GB | 89.197 | 89.197 |

完成速度比为0.997，单次差距不能当作可靠回退幅度，但明确没有“大幅提升”的证据。
共同回调窗口的4.87倍上涨与首 token 后移同时发生，不能作为整体加速宣传。
最早开始输出的时间也从约48.8秒后移到了约193秒。

候选记录268次独立 prefill，合计191.80秒；请求恢复阶段另有12.38秒，包含查询、
草稿及其他执行。参考的203.75秒恢复阶段同时包含完整 prefill，不能直接把两个
`resume_s` 相除。验证计算总计20.96/21.11秒，因调度改变实际批次组成，需结合下表看。

| 请求数／验证行数 | 参考平均 ms | 候选平均 ms | 参考／候选批数 |
|---|---:|---:|---:|
| 1／8 | 33.735 | 33.664 | 313／329 |
| 2／16 | 62.978 | 65.583 | 94／86 |
| 3／24 | 93.176 | 100.547 | 9／9 |
| 4／32 | 123.817 | 117.908 | 28／28 |

四请求验证的观测成本下降约4.8%，二、三请求未见收益。这是实际活跃批次的观测，
不是固定输入的算子速度比。只有28轮保持四请求，宽验证不足以改变整组的主要成本。

## 下一步

1. 优先最早进入的待处理提示词，同时仍在每块之间给已就绪解码执行机会。以请求ID
   排序，避免槽位复用让新请求插队。该候选已实现，CPU公平性/取消/补位检查及CUDA
   host构建通过；GPU验证排队，不能宣称已经改善TTFT或吞吐。
2. 验证每会话历史复用。已准备两条独立真实任务、各连续两轮的 HTTP C2 回放；比较
   轮换key与保留key，要求相同文本/usage、实际并发路由、合批验证和正的前缀复用位置。
   这是连续 agent 轮次的独立实验，不能替换上述冷请求结果，也不评价 SWE 任务成功率。
3. 宽验证候选暂不扩大效率测试矩阵。按上述成本和后续暖请求结果决定是否继续优化
   线性计算、attention 或状态搬运；有明确收益后才独立重复。

本轮只有一个种子、一组 C4。尚未完成 HTTP/bounded 生命周期和最终独立重复，
并发优化目标仍在进行。修复 FP8 数学路径改变了旧配置的输出，不将本轮结果直接
除以原始72请求基线来报告等工作量加速。
