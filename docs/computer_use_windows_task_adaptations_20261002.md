# Windows 场景适配约定 v1

此约定固定 022、035、043 的已有适配和评分解释，供后续两组使用同一条件。
对应的 [机器可读记录](computer_use_windows_task_adaptations_20261002.json) 绑定原任务、
实现和资格证据的哈希。它不表示 V0 已冻结，也不把脚本资格检查算作模型任务成功。
修改这些条件必须产生新版本，并重新标注受影响的试验。

## 022：保留原站点的四条失效链接

保留 TradePro 页面中 2024、2025 年 1099DIV、1099B 的四条原始失效链接，
不生成替代税表，不删改页面。47 条链接清单和固定材料清单分别保留；题目所需的
23 份原固定材料全部存在。两组使用同一批 PDF 字节、六个来宾机本地站点和
同一下载目录，期望哈希只留在宿主机。记录原哈希评分与严格的分类、无额外文件、
提交状态核验。下载或选择非必需失效链接产生的操作与耗时保留在轨迹中。

## 035：按审核完成投递原消息

采用已有 v1 投递实现：初次审核结束后投递原计划 900 秒内的 21 条消息，
再分别于后续审核结束后投递 1500 秒的销售请求及 1620 秒的最终纠正。
三个批次为 21/1/1，正文不变；原 30 分钟墙钟投递没有复现。
业务月份为 2025 年 12 月，消息时间锚点为 `2025-12-23T10:00:00+00:00`。
补建原后到销售消息所需的 `dm_emily` 会话入口。

只有已识别、已完成、桌面暂停且无不确定动作的审核回合才能触发下一批。
后续审核使用同一 Codex 线程和累计工具预算，不重置任务计时或提供评分答案。
投递回执、首次画面进入模型的时间及未知的正文曝光范围分别记录。
任务在全部消息投递前失败，仍保存真实失败；不由测试程序代替模型完成审核。

本地确定性工作簿核对替代原远程 LLM 裁判，检查七个字段、受保护表头和基线、
无额外行列，并要求三批消息已完成。不得将此分数标作原远程裁判分数。
已有四轮原生驱动资格检查使用脚本后端；真实 QW3 预跑误点并停止的结果保留。

## 043：同时保留原评分和冲突诊断

保留原手册、日历和任务要求，不修改会议来消除素材冲突。
分别报告原兼容分数、结构核验和严格业务诊断，不用单一成功率掩盖其差异：

- 原评分没有完整检查参与人和有限重复，且允许受保护会议时间偏移五分钟；
  结构核验另外检查这些项目，并使用原输入已有的显式有限会议实例。
- 手册对 M06、M19 包含 Marcus，原评分规格遗漏他。
  严格业务诊断按手册参与人，原兼容分数仍按原评分规格计算。
- 将各参与人正常工时解释为 09:00–18:00 时，洛杉矶、伦敦、新加坡没有共同
  时段。这个时段是诊断解释，原题没有给出相同精确范围；不能把该诊断的
  不可满足性说成所有其他合理解释均不可满足。

原评分满分且结构正确的资格样例不代表全部业务要求满足。
后续比较原分数、正确会议数量、改坏受保护会议数量、冲突数量和耗时；
严格业务结果保持原样，并明确解释所用时段，不放宽条件制造通过。
