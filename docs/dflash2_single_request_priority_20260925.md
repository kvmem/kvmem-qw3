# 单请求优先：用户指令与优化顺序

用户最新要求：先使单请求 KVMem DFlash 2 的吞吐接近公开测试，再开展多并发开发。
本记录调整执行顺序，保留历史证据与尚未完成的后续工作，不覆盖已冻结协议的哈希。

主配置保持 Qwen3.8-27B Q8_0 目标权重、E4M3 FP8 KV、官方 DFlash 2 草稿。
实现工作区 `/home/chaidi/qw3-dflash2`；主目录未集成。已有并发实验保留且不开启，
预填充合批的已知输出失败仍未修复，不在当前单请求优化中隐藏或宣称通过。

2026-09-25 重新读取[官方模型卡](https://huggingface.co/z-lab/Qwen3.8-27B-DFlash2#evaluation)：
单 H200、SGLang/FA3、T=1/top-p=.95/top-k=20、xhigh、最多 4096 输出。
五任务 C1 DFlash 端到端吞吐为 GSM8K 236.1、MATH-500 230.7、HumanEval 214.6、
MBPP 226.9、MT-Bench 184.0 tok/s。该表的 MTP 也提出七个 token；此前本机工程日志
诊断的 MTP 深度为四，输出上限 256、无 thinking，不是这组公开任务的直接复现。
模型卡未明确标注目标/KV 精度，不能仅根据草稿 BF16 标签断言所有运行精度。

优先顺序：

1. 固定当前 C1 控制组、profiling 与输出，定位目标验证的实际 CUDA 开销。
2. 保留串行 Q8 算术与状态语义，优化目标验证；改动必须通过算子与模型一致性。
3. 使用已冻结公开任务及 xhigh prompt，补齐 MTP-7 对照与单请求测量；KVMem
   全量容纳与稀疏检索分别标记，不能改变检索语义来冒充同一任务加速。
4. 做独立交替测量、质量与必要长历史/恢复检查，报告距公开绝对吞吐的差距。
   本机 RTX PRO 6000 Blackwell 与 H200 的差异单列，同机 Q8/FP8 none/MTP 控制
   仍必需。达到某个短样本数字不等于达到五任务公开测试。
5. 单请求阶段通过后，再恢复多并发实现和验收。

历史诊断中 DFlash 的目标验证约占 decode 的 82%；该占比确定优化方向，
不能代替本次 kernel profiling，也不是已经改善性能的证据。
