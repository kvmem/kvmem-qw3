# 本地视觉诊断与坐标契约修复

2026-10-03。P1 原定 48 次读屏请求已完成。最明确的发现是**坐标单位不匹配**：模型
看到了正确控件，却经常在明确要求像素坐标时仍输出 0–1000 坐标。应用已加入显式
坐标空间及确定性换算，并完成一次真实 Windows 点击验证。完整业务任务还需复测。

## 坐标单位的验证与改进

原图六次定位按像素评分全部失败；事后统一按 `x×1280/1000, y×800/1000` 换算，六次
均落入原目标框。例如 Save draft 输出 `(93,654)`，像素点击会落空，换算后约
`(119,523)` 正确命中。此事后分析仅形成假设，**没有改写原始 0/6 成绩**。

随后冻结独立的 24 次对照：六个已见目标为开发组，同六个界面上的六个新控件为保留
目标；分别测原像素契约与明确的归一化契约。后者要求 `coordinate_space=normalized_1000`
及整数 x/y，再由固定程序按实际尺寸转换，不按答案选择单位。

| 目标 | 像素契约 | 显式归一化 + 程序换算 |
|---|---:|---:|
| 六个开发目标 | 0/6 | 5/6 |
| 六个新目标 | 0/6 | 6/6 |
| 合计 | 0/12 | 11/12 |
| 请求耗时中位数 | 0.470 s | 0.581 s |

唯一未通过的归一化回答将整数写成字符串，严格校验判失败；没有隐式纠正后算成功。
新目标此前未询问，但截图已见，因此这是新目标测试，不是新界面泛化证明。两轮题目
现均已使用，后续不得继续称为未见保留题。追加 24 次不替代原 P1 的 48 次分母。

应用实现如下：

- `act` 可显式指定 `pixels` 或 `normalized_1000`。视觉估计用后者，accessibility
  控件中心用前者；旧调用不填仍使用像素。不能凭数字大小猜测或自动纠正单位。
- 在最新观察身份及暂停校验后，按该观察的尺寸转换 click、scroll、drag。布尔值、
  字符串、越界归一化坐标与非定位动作的错误单位会在投递前拒绝。
- 原始动作和换算结果持久化；相同 action ID 不重复执行。丢失响应后重开应用，先查询
  执行器回执并恢复原换算记录，不重新换算或重发动作。执行器继续只接收像素。

相关 45 项接口/应用测试通过。真实本地模型在新的当前 Calc 截图上返回 `(319,260)`，
经应用边界换算为 `(408,208)` 后点击；未经编辑的结果图显示名称框 C2、选中 C 列第
2 行、值为 4，与 Cable 的 Quantity 相符。该单次验证使用真实模型、宿主应用边界和
Windows 执行器，未走完整原生 Codex 回合，不算完整任务成功率。

原生客户端 22 已通过 107 项 Windows/Codex 运行契约，属于脚本化后端检查。包 SHA-256
为 `4ee8a31c7706046d9cf7372148d88d3bf5a56ecc64eb3e39e2297f1617ba2f4d`，回执在
`windows-client-22-qualification-02/result.json`。第一次归档前置检查失败未派发客机
测试，单独留档；补齐归档身份后才进行本次原生检查。
