## 已实现与独立验收

显式 `-SoftwareRoot` / `--software-root` 开启本地 Windows 软件模式。模型选择项目和
已审核配置档，不接受任意 shell、安装 URL 或包名。当前配置档固定 Python 3.13.16 x64、
requests 2.34.2、pytest 9.1.1 及 11 个轮子依赖项，来源与 SHA-256 固定在
`apps/computer_use/qw3_computer/software_catalog.json`。

下载保留 TLS/主机名验证，并携带固定 certifi 公开 CA 包；独立核对安装包/轮子哈希。
不使用环境代理。pip 从审核缓存离线安装，启用 hash 校验。工作目录有进程锁，动作
有持久化身份，阶段与错误留存；不能因重复调用而重复启动安装。

任务在后台执行，模型轮询状态。只有实际工具校验通过，应用才允许成功结束。
普通中止可保持原身份恢复；安装器中断/未知状态仍需人工核对，不能宣称自动回滚。
已补回“worker 尚未开始即暂停”的持久化状态，并保证桌面执行器断连时仍暂停软件任务。

第三次的独立检查由 agent 回合结束后的测试进程执行，包含：

- 新 cmd 激活项目 `.venv` 后运行 `python main.py`，结果 42，Python 和依赖版本正确，
  `sys.executable` / `sys.prefix` 指向目标项目。
- 另一个新 cmd 运行 pytest：`1 passed`；第三个新 cmd 执行 pip check：无破损依赖。
- 两个原输入文件的哈希保持不变；HKCU 用户 PATH 保持不变；存在依赖锁和终端启动器。

当前试次没有独立比较 HKLM 系统 PATH；安装参数明确禁用 PATH 写入，后续正式验收仍需
补充机器级 PATH 前后比较。实际双击启动器、普通非管理员账户和应用重开后的恢复体验
也需要独立验证，不能以本次新进程检查替代。

Windows 专项证据证实：默认 SSL 上下文失败，携带 CA 的上下文返回 HTTP 200，二者均
启用证书和主机名验证。只补 ProgramData/ALLUSERSPROFILE 仍不能解析目录；进一步保留
SystemDrive 后，`SHGetFolderPathW(CSIDL_COMMON_APPDATA)` 从 0x80070003 恢复成功。

第三次阶段耗时：下载 Python 3.12 s，安装及基础校验 29.64 s，创建 venv 10.36 s，
下载/安装依赖 31.36 s，工具内部项目校验 3.87 s。共 11 次模型请求、10 次工具调用，
工具错误 0 次。模型请求总等待 36.79 s，P50 2.45 s；后台安装与模型等待有重叠，不能
相加得到总时长。包含 VM 恢复、客户端部署、录像与独立验收的宿主总时长为 260.84 s。

GPU 设备显存采样峰值约 67.30 GiB，引擎进程 RSS 采样峰值约 28.93 GiB；尚未测得完整
Windows 应用/VM 内存。这是现有 1M 上下文实验配置的资源表现，不能作为普通电脑适配
结论，也尚未区分常驻权重、KV 与临时工作空间。资源优化需单独固定配置对照。

客户端 19/20/21 分别通过 101/102/104 项原生 Windows/Codex 运行契约；这些使用脚本化
推理后端，不当作真实任务成功。真实任务另外保留完整模型请求回执、日志、结果、连续录像。
