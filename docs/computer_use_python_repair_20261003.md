## 故障与修复边界

独立准备脚本先安装两个正常项目，记录源文件及整个无关项目的哈希，再只向目标项目
注入两个故障：移走 requests 模块目录但保留安装元数据；将项目终端启动器指向另一项目。
任务开始前再次检查目标程序和实际启动器失败、无关项目正常。准备脚本不是模型修复，
不计入任务成功。复测前先验证上一轮已修复，再重新制造字节一致的启动器故障和相同的
缺模块状态。

新增 `repair_python` 作业先诊断解释器身份、实际导入、依赖版本及启动器，然后使用固定
哈希清单中的 wheel 修复依赖，并备份旧启动器。两个新进程和 pip check 验证修复结果。
每个阶段有日志和检查点，沿用现有暂停、取消、未决状态与重启处理。

该工具只修复匹配配置档的受管理项目；解释器身份不符、解释器丢失、依赖锁被修改或
未知 venv 均保留现场并报错，尚不能自动处理任意系统 Python / Conda / PATH 冲突。
本次使用已校验的本地 wheel 缓存，不代表冷下载或系统重新安装速度。
