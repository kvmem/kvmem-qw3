# 单请求 KVMem：草稿长度与上下文重置实验

Qwen3.8-27B Q8_0 主模型＋E4M3 FP8 target KV，官方 BF16 草稿权重，草稿 KV/attention
沿用 FP32。只测单请求；没有开发多并发，没有集成或部署。目标仍未完成。

全部实验沿用冻结的 32K 历史、256-token 工作窗口、CPU mean-K 索引、greedy，
每路线 1 个独立预热＋16 个正式请求。热请求计时含 query 检索、重放和收尾，
不含历史摄入；decode 另列。保留全部错误和截断。每组候选 17/17 输出 IDs 和
响应字节与冻结 none 完全一致，正式输出总数均为 2159。三路线仍仅答对 1/16，
各有 3 次长度截断；输出一致不代表检索任务质量合格。

build14 的 3/5 草稿实验只改变草稿长度：3 个草稿增加了验证轮数，5 个草稿略有收益，
仍未超过同机 MTP4。不是逐样本挑选最优长度，默认七草稿没有改变。

build17 在 common semantic query replay 边界增加默认关闭的
`QW3_DFLASH_KVMEM_RESET_QUERY_CONTEXT`。目标模型完成稀疏窗口切换后，清空旧草稿
上下文，由已提交的 query replay 特征重新建立它；在重置后才保存 P checkpoint。
目标 KV、检索规则、recurrent state 和验证算法不变。不是完整的历史草稿特征重建，
也不宣称覆盖所有 archive/transcript 分支。

同 build17 开关配对热请求吞吐比 reset/off = **1.049368**，变化 **+4.94%**。
off 的 reset 日志为 0，on 为 17，每次记录 previous_rows=2048/base=32768。
这是一组完整工程实验，固定顺序，尚无独立交替重复；不能作为正式性能资格，
不能用跨构建的 baseline 比值替代同构建对照，开关继续默认关闭。

重置开启后的生命周期 guided_4k/long_4k 共 34 个步骤通过，包括刷新、取消、分叉、
历史增长和恢复；主输出逐 ID 一致，引导私有查询和刷新策略检查通过。
CPU/GPU 采样 probe 的 8 组参数检查通过，实际触发 16 次重置。它检查同路线的
采样实现一致性，不替代跨算法任务质量或全量长历史资格。

剩余工作包括稀疏 KVMem 的采样与 128K bounded C1、完整任务质量、资源峰值细分、
全部公开任务及独立重复。公开参考引擎资格仍未通过，不能声称接近或超过同条件
公开结果。检索事实完整性问题沿用 stage10 诊断，没有修改策略来隐藏它。
