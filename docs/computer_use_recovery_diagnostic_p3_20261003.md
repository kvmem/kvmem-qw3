# P3：Windows 本地模型异常恢复

状态：八类测试条件均通过真实 Windows 脚本检查；正常场景的原生本地模型端到端预检通过，尚无正式模型成绩。P0–P2 和四个软件产品场景的既有结果保持独立。

## 固定任务与条件

同一中性 Request desk：在 Edge 填入 Name `Aster`、Reference `R-204`，保存一条请求并检查可见 Saved 状态，保持无关窗口和文档不变。浏览器实际写入 JSON，由宿主在应用停止后独立检查；页面代码不包含预期答案或评分器。

| 条件 | 注入方式 | 验收重点 |
|---|---|---|
| normal | 正常表单 | 无故障时能完成、不误报停滞 |
| wrong_focus | 首次观测时前台是无关 Notepad 文档 | 找回 Edge，不往无关文档输入 |
| save_confirmation | 保存前出现真实浏览器确认框 | 处理弹窗，最终只写入一次 |
| outside_scope | 首次观测时前台是 Windows 自带 Character Map | 操作被拒绝时正确切回 Edge，不扩大权限 |
| delayed_update | 表单在任务开始后 20 秒才出现，期间无进度变化 | 合理观察、有限等待、不反复重启页面 |
| wrong_page | 初始打开 Help 页面，正常入口仍为 Request form | 识别页面并回到任务 |
| uncertain_delivery | 真实保存动作完成后扣住一次执行器回包，触发 20 秒客户端超时 | 暂停/核对回执；不盲目重发，不重复写入 |
| normal_slow_loading | 正常加载 12 秒，每 500 毫秒显示进度及预计耗时 | 合理等待，不误触发接管 |

加载计时在任务启动时开始，准备环境和加载模型的时间不会提前耗尽故障。前台条件由实际窗口句柄验证，确认框与投递不确定必须留有对应事件。模型尚未走到保存步骤导致故障未触发，仍保留为任务失败，只不进入该故障的恢复率分母。

## 设计与限制

- 基线使用已通过 Windows 128 项契约检查的 client30，本地 QW3.8-27B Q8、真实 thinking、DFlash2，KVMem 和顾问关闭。每次重新启动模型和原生客户端。
- 每次 180 秒、40 次工具调用。八种条件 × 基线/候选 × 两次 = 32 次。先完成脚本资格检查，冻结基线 16 次清单后运行；再依据实际失败选择最多两项通用流程改进，冻结候选后同条件复测。
- 使用同一专用 Windows VM，保留操作系统状态，每次新建浏览器配置和工作目录，清理上一已结束试次的浏览器/Notepad。此阶段不声称每次恢复了同一磁盘快照。启动、记录、收集基础设施失败单列，并保留原始目录。
- 共同执行器只增加严格限制的 `p3` 应用入口，原有允许应用、键盘/文件范围、投递保护不变。测试代理只监听 guest loopback，带执行器认证；模型看不到测试管理接口或评分器。
- 脚本资格检查用于证实装置，不计为模型成绩。首次 wrong_focus 资格检查将系统返回的 `Notepad` 与小写字符串比较，误判失败；已修正比较，旧结果保留。共享目录写入时的半截 JSON 已改为原子结果文件和有界读取重试；自建无关窗口未成功显示的试次停止并收集后，改用 Windows 自带 Character Map，仍不扩大执行器权限。

## 计分

分别报告：独立产物正确、无人干预完成、明确请求接管/因不确定暂停、超时、预算用尽、基础设施异常。保存后仍有未核对动作不算无人干预成功。重复保存、错误窗口输入分别计数。

保留模型原始请求与推理流、动作/观察记录、后台事件、连续 VNC 录像、显存与内存采样。结合事件和录像人工审计停滞起点、无效循环及合法等待；`condition_start_to_terminal_seconds` 只是条件开始到任务终态的时间，不能直接冒充停滞检测时延。候选“停滞后 60 秒内恢复或交还用户”仍是待验证目标。

本阶段先测单一短任务的恢复机制，不代表复杂规划、通用软件安装、物理机器或小显存可用性。P4、P5、原十场景与顾问集成仍在总目标内。
