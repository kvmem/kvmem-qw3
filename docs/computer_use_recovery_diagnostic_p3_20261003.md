# P3：Windows 本地模型异常恢复

状态：2026-10-03，本轮流程修复和复测完成。三个冻结客户端共 48 个有效试次，另保留
一次基线基础设施中断，总计 49 个正式尝试。最终 client33 无人干预完成 14/16、实际
产物正确 16/16；两次回执丢失暂停单列。P0–P2 和四个软件产品场景的结果保持独立。

## 固定任务与条件

同一中性 Request desk：在 Edge 填入 Name `Aster`、Reference `R-204`，保存一条请求
并检查可见 Saved 状态，保持无关窗口和文档不变。浏览器实际写入 JSON，由宿主在应用
停止后独立检查；页面代码不包含预期答案或评分器。

| 条件 | 注入方式 | 验收重点 |

只不进入该故障的恢复率分母。

## 从失败到流程修复

1. 基线不同任务共用 GUI 编号。正常场景因前一预检已用 `click-name-field` 而收到 409，
   新客户端仍共享持久 VM 账本。修复使用任务与模型动作编号生成稳定内部身份；同一
   动作仍只派发一次，旧任务仍查询自己的旧回执。没有删除历史来规避冲突。
2. 基线 wrong_focus 把 `action_id` 放进 `action` 内，14 次本地校验失败、远端输入零次，
   135.37 秒后请求接管。旧错误只说编号长度/字符不合法，模型反复换编号。修复严格指出
   JSON 路径，不搬移或猜测参数；连续三次已确认未执行的拒绝暂停。同一前台连续至少
   三次观察且三十秒无变化才暂停；进度变化重置观察窗口，活动软件作业用原轮询流程。
3. client31 两轮 outside_scope 新增失败：尝试最小化、点击或 ALT+TAB 均被前台权限
   拒绝，在 20.17 / 15.62 秒暂停而没有保存。初始修复减少了循环，但无人干预完成从
   13 降为 12，因此未声称整体改善。执行器本来就允许 `open_app` 激活任务应用；
   client33 在指令与结构化错误中明确这条恢复路径，保留权限和三次拒绝阈值。最终
   两轮都先激活 Edge，再完成任务，没有操作保护文档。
4. client33 同时增加观察绑定的 `click_control`。模型选择当前系统控件编号，程序取得
   像素中心并通过既有执行器点击。没有匹配控件时使用显式 `normalized_1000` 视觉坐标。
   精确校验、操作后核验和旧回执查证继续适用。

任务隔离、报错、恢复提示与定位接口共同改变，不能把完成改善分别归给某一项，也
不能用本轮声称“所有图像理解已无问题”。定位诊断的 0/12 → 11/12 更支持坐标约定是
当时的主要瓶颈；新目标仍来自已见截图，自绘画布和陌生界面需另测。

55 次控件编号点击逐一验证：编号对应唯一当前观察控件，保存映射等于其像素中心，
执行器恰有一次成功事件且实际动作相同。53 次本地收到完成回执；另两次本地为不确定
但远端确已保存一次。错误窗口文本输入与重复派发均为零。控件几何绑定正确不能代替
模型选对语义目标的检验。

两次人为扣住保存回复后，最终版本分别在故障后 20.69 / 20.48 秒暂停，正确产物保留、
没有重复点击。这是保守停下而非自动恢复。60 秒不是所有条件的保证：无进度延迟页
仍耗时 92.06 / 101.70 秒，其中包含模型请求与后续操作；正常慢加载 75.28 / 72.73 秒
保持成功。连续观察阈值不能约束单次长推理。

## 中断与资格检查记录

原 `p3-baseline-r2-01` 宿主队列、模型、转发与录屏进程已不存在；客机显示推理流断开、
桌面停止，录像没有正常终结。收集原状态后记为 `infra_invalid`，不标成完整录像，原
冻结清单不变。单独冻结新身份 `p3-baseline-r2-01-retry1` 同条件补测，43.90 秒/六次
工具调用通过。基线共十七次尝试、十六有效；十五个原有效试次与一个补测分别审计。

装置资格检查不计模型成绩：八类条件取得八次成功，累计十次资格检查、两次失败；
另外保留共享目录半截 JSON 读取中断后的沿原身份收集。修正包括 Notepad 名称忽略
大小写、原子结果文件与有界读取重试、用系统 Character Map 替代未显示的自建窗口。
实际延迟更新检查 20.23 秒、慢加载 12.24 秒，回执扣留确实发生且保存一次。
正常模型预检 `p3-native-preflight-01` 35.67 秒/五次调用通过，不加入正式分母。
