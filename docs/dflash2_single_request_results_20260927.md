# DFlash 2.0：KVMem单请求优化结果

**本轮优化、测试与开发源码接入已完成。** 按用户最新要求，130 tok/s仅是参考，
不是完成门槛。主线为Qwen3.8-27B **Q8_0目标权重＋FP8目标KV、K128K/G64K、
C1、T1/top-k20/top-p0.95**。没有新增BF16目标权重支持，也未进入并发开发。

## 按空间排序的优化与取舍

|改动|证据与效果|决定|
|---|---|---|
|等待工具/XML/围栏闭合时继续投机|4K/128K greedy、CPU/GPU sampling、紧急刷新、取消恢复通过；闭合候选仍进入p/q验证，保留512 token紧急余量|保留|
|verifier plan cache|与上项合开的旧完整45请求78.63→78.92 tok/s，仅约+0.37%；物理页索引仍每次更新|保留，不宣称显著吞吐收益|
|长历史attention验证路径|两种子完整45请求78.91→98.37、79.69→101.54 tok/s；verify降至约30ms/批|本轮主要观察收益；保留短历史负桶和轨迹差异|
|刷新私有查询DFlash|192451历史配对请求32.19→45.67、41.66→51.70 tok/s；生成查询13.43→7.63、12.06→7.36秒|保留；输入、输出及检索策略匹配，仅发生查询的阶段受益|
|固定5120维FFN gate/up＋SwiGLU|算子耗时减少3.63%；三个真实前缀两种子吞吐+1.51%/+1.14%，配对一致|保留小幅收益，不能把算子收益当任务收益|
|私有查询五草稿|真实刷新长请求45.87→46.76、51.83→52.57 tok/s，+1.94%/+1.42%|保留；主请求仍七草稿|
|临时缓冲区回收|真实刷新开关对照峰值均减少约0.80GB；吞吐+1.56%/+0.07%，第二组基本持平|保留，主要是显存收益|
|普通attention分数缓冲区延迟分配|最终四阶段峰值均减少约100.7MB；完整吞吐基本持平，刷新场景−1.07%/−0.48%|保留显存收益，同时记录小幅负变化|

这些收益来自不同对照，不能把百分比相加。更细的排序和未采用方案见
[优化空间记录](dflash2_remaining_optimization_review_20260926.md)。

## 真实刷新与剩余瓶颈

两组完整45请求没有中途刷新；真实刷新使用另外两个Scriggo前缀，包含一次实际刷新：

|种子|最终长请求tok/s|查询 / KV重选秒|两请求加权tok/s|
|---|---:|---:|---:|
|1000|46.7630|7.3661 / 1.1813|49.7024|
|1001|52.8140|7.2506 / 0.9977|55.1567|

完整集合verify仍占native decode约**80.96% / 81.25%**，draft约6.1ms/批。
完整集合没有零草稿串行步骤；刷新场景仍有必要的边界/桥接和查询开销。
最终独立报告同时列出draft、verify、plain、零草稿、bridge和刷新耗时；
这些native阶段包含主机提交与GPU执行，部分串行指标与prefix重叠，不应直接相加。

本轮没有稳定达到130 tok/s。按profiling排序后，FFN与查询宽度的进一步收益较小；
已记录结果并结束本轮单请求筛选，不据此声称已经到达硬件极限。

## 正确性、代码和限制

- 最新10阶段GPU验证及独立重解析通过：三模式off/on每侧19组完整词表logits
  有限且逐字节一致；1K/128K各4位置×8宽度的逐层残差和全logits精确匹配；
  4K/128K各28请求覆盖greedy、CPU/GPU sampling、刷新、紧急边界和取消恢复。
- 128K合成状态测试使用K64K/G32K；正式吞吐使用K128K/G64K。128K组未命中
  query_cancel释放，4K组命中6次，不扩大取消覆盖声明。
- 新attention单独启用时曾使真实刷新请求35.62→32.54、43.77→41.55 tok/s，
  因生成查询更长；此负结果保留，随后私有查询投机才改善对应请求。
- 对齐加载、流式加载、寄存器限制、INT8 MMA、attention interleave等未改善的
  变体未纳入；发生非法访存的pipeline候选已回退，失败证据保留。
- 没有GPU硬件性能计数器权限，不能断言DRAM或SM已饱和。采样峰值可能漏掉
  瞬时峰值；完整JSON保留采样间隔与资源记录，最终显存余量很小。
- 这是冻结DeepSWE请求的推理回放，**不执行工具，不报告SWE任务成功率或质量不下降**。
  公开FP8目标权重结果也不能当成本机Q8_0同配置基准。

最终源码已接入`src/qwen_executor.cpp/.hpp`、`src/qwen_native_backend.cpp`、
`src/kernels_cuda.cu`、`src/flashinfer_prefill_adapter.cu`、`src/mmvq_q8.cu`。
新实验开关仍默认关闭，使用本结果需采用复现页的冻结配置；现有服务未替换。
