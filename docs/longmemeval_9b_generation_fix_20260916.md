# 9B LongMemEval-S 生成失败诊断与采样修正

用户于2026-09-16要求暂停实验，先检查失败原因、修复后继续。原实验已停止，
结果与原请求全部保留；中断中的第80题是人为中断，不计模型失败。

## 已验证的现象

原队列79个终态中有31个没有生成可用答案。响应以 `length` 结束，
summary/answer 的最终 content 为空，reasoning 则大量重复。
第一条失败摘要 `118b2229` 的一句话重复3932次；第一条失败回答
`0a995998` 的若干相同条目重复约2113次。原解析器把这些字段正确识别为
reasoning，故不是漏收最终答案，也不能把这些内容当成有效摘要继续传递。

旧流程使用温度0、presence penalty 0、thinking不封顶，max_tokens省略；
服务按剩余262144-token上下文生成。这使循环持续到约162K/230K输出。
失败标签说明输出终止现象，并不单独证明模型、量化或MTP中的某一个是根因。

## 对照方法

完整产物：`benchmark/longmemeval_9b_failure_diagnosis_20260916/`。
预先固定最早失败摘要和最早失败回答两个请求，在相同Q8权重、FP8 KV、
原提示、seed0和prefill配置下，比较MTP4/关闭MTP与旧贪心/推荐采样。
诊断统一使用8192输出上限，仅限制诊断成本，不将其带入正式实验。
保存全部请求、response、服务命令和日志，不能把达到诊断上限直接等同于
已复现完整262K上下文耗尽；结合原长响应与重复内容判断退化现象。

已见：旧参数+MTP4两个请求均到8192还没有最终内容；推荐采样+MTP4
分别在2820、6874输出tokens后自然stop，产生非空最终内容。
关闭MTP时，旧参数的摘要在4485 tokens后结束，但回答仍到8192无最终内容，
且同组三句话重复约27次。因此关闭MTP也会出现思考循环，MTP路径同时确实影响
贪心生成轨迹；目前不宣称
已经证明MTP数学等价或发现了具体引擎bug。完整8项结果以summary.json为准。

全部8项已完成：推荐采样在MTP4/关闭MTP下的摘要输出分别为2820/3491 tokens，
回答输出分别为6874/5374 tokens，4项均自然stop并有最终内容。
旧参数4项中的3项达到诊断上限。这个小型对照支持采用推荐采样作为已验证的
缓解措施，不能保证全部102题零失败，也不用于判断准确率。

top_k=20、min_p=0、presence_penalty=1.5、repetition_penalty=1.0。

1024/128检索分块和排序；继续thinking且不增加thinking/输出上限。
