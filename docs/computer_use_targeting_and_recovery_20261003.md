# Windows 定位工具与恢复流程改进

2026-10-03。当前选择是：系统提供匹配的可见控件时，模型选择控件编号，程序负责取得
像素中心；没有匹配控件时，模型明确返回 `normalized_1000` 视觉坐标，程序根据当前截图
换算；每次操作后查看结果。界面中的控件名称只作任务数据，不能改变工具权限。

## 依据与判断范围

- 既有坐标对照：像素要求 0/12，显式归一化加程序换算 11/12，剩余一次为字符串类型
  错误。六个新目标来自已见截图，不能证明陌生界面、密集文字和自绘画布没有视觉问题。
- 既有推理对照：截图 thinking 关闭/开启分别 14/24、24/24，等价文字分别
  16/24、24/24。这是十二道短页面题各重复两次，复杂长任务仍需独立验证。
- 既有恢复失败：模型把动作编号放错层级，十四次错误调用未派发任何桌面输入。另一类
  问题是不同任务共用执行器历史编号。两者属于工具协议和恢复流程问题，不能当作
  点击准确率证据。

## 两项恢复修复与独立定位候选

client31 包含按任务隔离动作编号、精确字段错误反馈和有界恢复。连续三次已确认未
执行的拒绝暂停；连续至少三次观察且同一前台画面三十秒没有变化暂停；变化中的加载
进度会重置时间窗口，活动软件任务使用自己的回执和轮询。暂停阈值不保证一次长推理
也在六十秒内结束。Windows 原生 Codex 契约检查 138/138 通过。

client32 定位候选进一步提供 `act` 的 `click_control`：

```json
{
  "desktop_id": "从当前观察复制",
  "observation_id": "从当前观察复制",
  "action_id": "click-name-001",
  "action": {"kind": "click_control", "control_id": "ctl_0123456789abcdef"}
}
```

控件编号由程序生成并绑定桌面和观察，模型不能通过名称模糊匹配、猜测坐标或复用旧
编号。只给系统可见、启用、非密码控件且中心在截图/控件范围内的条目提供编号。
编号不存在、观察过期、无障碍接口超时或混用归一化单位均拒绝，指出具体字段。
控件点击仍通过既有 GUI 执行器进行一次左键输入，保留焦点与权限检查，不执行任意
脚本。动作前后屏幕仍必须核对；编号并不能证明模型选择的按钮符合用户意图。

原始选择、匹配控件、最终像素动作和回执均持久化。响应丢失后查询原回执，不根据新
界面再次定位或重复点击。视觉 click/scroll/drag 保留原显式坐标接口，用于自绘画布等
系统未暴露的区域；旧像素调用保持可用。

  新测试涵盖重名控件、旧编号、错误单位、坏坐标和丢失响应后的重开核对。

  已不存在，原录像未正常终结。收集原状态后，以新身份同条件补测，不复用旧目录、
  不清空执行器历史编号。十五次原基线与一次补测分别通过证据审计。

  也不宣称当前方法在所有应用上最优。
