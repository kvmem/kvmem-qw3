3. 冻结纯本地结论，再根据实际停滞原因设计和实现 Super-Advisor。
4. 验证顾问接口和真实端到端运行，做本地/顾问协助同条件对照，交付可运行版本和报告。

本目标扩展了先前仅规划纯本地测试的范围；原诊断计划中的“顾问延后”仍适用于
P0–P6，但顾问集成现在是后续必须完成的里程碑。新增运行数从零记录。

## 顾问阶段 P7：以实际瓶颈确定接入

参考用户指定的 [dsh-super-advisor](https://github.com/kvmem/dsh-super-advisor)，
在完成本地诊断后再审查其届时源码并确定最终接口。以下是验收约束，不是已实现功能：

- 新增默认关闭、可配置模型端点的 `ask_advisor` 工具，不改变纯本地默认运行。
- 本地模型遇到已观测的持续停滞时，可发送任务目标、约束、已尝试操作、当前状态
  和一个明确问题；按需要及端点能力附带选定截图。不得默认上传完整桌面历史。
- 顾问返回诊断和建议，原 agent 核对当前画面及工具权限后执行。顾问不直接控制桌面，
  不绕过动作投递、暂停、接管和不确定结果处理。
- 使用显式配置的模型、凭据、数据范围及预算；不继承本机个人云凭据。没有配置
  可用端点时继续本地测试，明确记录真实顾问验收尚未完成。
- 控制每任务调用次数、输入/输出量、等待时间；支持取消。调用结果未知时不能
  自动重发而产生重复消费。错误返回可审计，不伪装成有效建议。
- 用户能辨认当前是否使用顾问、发送内容范围、调用结果及新增耗时。

接口检查覆盖有效建议、无效响应、超时、取消、不确定结果、预算耗尽，以及暂停
后不能再派发动作。真实模型验收与脚本化后端检查分别记录。

用户已指定首个顾问为 DeepSeek V4.1 Flash，官方接口模型名为 `deepseek-flash`，
端点为 `https://api.deepseek.com`，依据 [DeepSeek 官方接口文档](https://api-docs.deepseek.com/)
于 2026-10-02 核对。用户提供的密钥存于 Git 忽略的本地私有文件，目录权限 0700、
文件权限 0600。当前仅保存接入配置；尚未调用该 API，也未在应用中启用顾问。

## 顾问阶段 P8：测收益与代价

从冻结的本地测试中选择四个有代表性的停滞样本、两个本地已能完成的对照样本。
六个样本分别在顾问关闭/开启下各重复两次，计划 24 次；在看对照结果前冻结选题、
端点身份、触发策略、评分、总时间预算、动作预算和顾问调用预算。

两组使用相同本地模型、thinking、KVMem、DFlash2、快照、任务输入与验收规则。
顾问等待计入同一任务总时限；不会因开启顾问额外增加任务预算来制造胜出。
记录原始成功次数、自动恢复、接管、首次错误、误触发、额外时延、顾问 token、
调用次数及可取得的费用信息。小样本结果仅作为探索性证据。

纯本地、顾问协助、人工接管分栏；仅靠顾问完成的任务不能算本地模型能力提高。
如果顾问未改善成功率，也应如实交付集成与负结果，而非挑选成功录像。
